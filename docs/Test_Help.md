## 3. Классы и схема

### Создание класса - ОК!
**Используем:** Schema → Edit Class Schema → + Add  
**Делаем:** вводим имя, выбираем annotation_type (bbox / polygon / polyline / obb / keypoints) → OK  
**Получаем:** класс появляется в Classes Panel с цветным маркером

### Изменение класса - ОК!
**Используем:** Schema → Edit Class Schema → выбираем класс  
**Делаем:** меняем имя, цвет, subclasses, display style → OK  
**Получаем:** изменения применяются; canvas перестраивает цвет аннотаций

### Скелет для keypoints-класса  - ОК!
**Используем:** Schema → Edit Class Schema → класс с типом keypoints  
**Делаем:**
1. "+ Add keypoint" × N (вводим имена: nose, left_eye, right_eye…)
2. В поле **Edges** вводим пары: `0-1, 0-2, 1-3` → Enter → OK

**Получаем:** скелет сохранён в `class_schema.json`:
```json
{
  "id": 0,
  "name": "person",
  "annotation_type": "keypoints",
  "skeleton": [
    {"name": "nose",      "edges": [1, 2]},
    {"name": "left_eye",  "edges": [0]},
    {"name": "right_eye", "edges": [0]}
  ]
}
```

## 4. Инструменты разметки

### Select [V] +
**Используем:** тулбар ✦ Select / клавиша V  
**Делаем:** клик на аннотацию → выделяется; тащим угловой маркер → изменяем форму; Delete → удаляем  
**Получаем:** аннотация подсвечивается, Annotations Panel выделяет соответствующую строку; геометрия обновляется

### Polygon [P] +
**Используем:** выбрать класс типа `polygon`; тулбар ⬠ Polygon / клавиша P  
**Делаем:** кликаем вершины контура → при клике близко к первой точке замыкаем (или Enter / двойной клик); RMB = удалить последнюю точку; Esc = отмена  
**Получаем:** замкнутый полигон на канвасе; в Annotations Panel — тип SEGMENT

### Polyline [L] +
**Используем:** класс типа `polyline`; клавиша L  
**Делаем:** кликаем точки → Enter / двойной клик = зафиксировать; RMB = undo последней  
**Получаем:** открытая полилиния; тип POLYLINE

### BBox [B] +
**Используем:** класс типа `bbox`; клавиша B  
**Делаем:** зажимаем ЛКМ и тащим прямоугольник  
**Получаем:** ось-выровненный прямоугольник; тип BBOX; угловые маркеры для resize

### OBB [O] +
**Используем:** класс типа `obb`; клавиша O  
**Делаем:** зажимаем ЛКМ и тащим → отпускаем → тащим второй раз для поворота  
**Получаем:** повёрнутый прямоугольник; тип OBB; 4 угловых маркера

### Crack [C] +
**Используем:** класс типа `polygon`; клавиша C  
**Делаем:**
1. Кликаем вдоль трещины (полилиния); Enter / dbl-click = зафиксировать
2. Параметры в Tool Props Panel: **buffer_width** (ширина буфера), **cap_style**

**Получаем:** аннотация типа SEGMENT (буферизованный полигон); в Annotations Panel кнопка **Edit source** активна

### Crack — Edit source +
**Используем:** выделить crack-аннотацию → кнопка **Edit source** в Annotations Panel  
**Делаем:** добавляем / убираем точки исходной полилинии → Enter  
**Получаем:** полигон пересчитан с теми же параметрами буфера; Ctrl+Z отменяет

### Pose [K] +
**Используем:** класс типа `keypoints`; клавиша K  
**Делаем:**
- *Без скелета:* кликаем точки → Enter / dbl-click = commit; RMB = undo; Esc = cancel
- *Со скелетом N точек:* кликаем N точек → авто-commit; превью показывает имена и рёбра
- *Частично:* разместить < N точек → Enter → остальные добавляются как невидимые (v=0)

**Получаем:** аннотация POSE; в Annotations Panel — тип POSE

**Редактирование:** Select (`V`) → клик по позе → перетащить ключевую точку → точка переезжает (берётся ближайшая к курсору, даже если точки стоят вплотную); атрибуты и подкласс сохраняются; Ctrl+Z возвращает точку

### Point [.]
**Используем:** класс любого типа; клавиша `.` (точка)  
**Делаем:** один клик ЛКМ → аннотация создаётся немедленно (Enter не нужен); Esc скрывает превью  
**Получаем:** одиночная точка (ghost-кружок 6 экр.пикс.); тип POINT в Annotations Panel

---

### Classify [кнопка]
**Используем:** создать класс типа `classification`; выбрать его в Classes Panel  
**Делаем:** в Annotations Panel появляется кнопка **`+ Classify as "<имя>"`** → нажать  
**Получаем:** IMAGE LABEL-аннотация для текущего изображения; повторный клик → предупреждение "Already labeled"

> Все drawing-инструменты при активном classification-классе блокируются автоматически.

---

### Brush / Mask [M]
**Используем:** класс любого типа; клавиша `M`  
**Делаем:**
1. Наводим курсор на изображение → под ним пунктирный круг размером с кисть; меняем `Brush size` → круг меняется
2. Рисуем кистью: ЛКМ + drag → закрашиваем область
   Shift: кликнуть в точке A, зажать Shift → от A к курсору пунктир; Shift+клик в B → прямая линия A→B; ещё Shift+клик → продолжение ломаной; после Enter новая маска не соединяется со старой
3. **Tool Props:** `Brush size` (px) и `Mode` (draw / erase)
4. Enter или double-click → commit → маска сохраняется
5. Esc → discard (без потери данных, см. Re-edit)

**Получаем:** аннотация типа MASK; в Annotations Panel отображается как MASK; PNG-файл сохраняется в `.annproj/masks/`

#### Re-edit маски
| Способ | Шаги |
|--------|------|
| Загрузить конкретную маску | Select → выделить нужную маску → нажать M → маска загружается в canvas |
| Авто-загрузка при стирании | M → Erase mode → первый мазок на пустом canvas → загружает последнюю маску текущего класса |

> **Esc при ре-едите** → оригинальная маска возвращается на место (данные не теряются).  
> Enter при ре-едите → старая маска заменяется новой.

### 7.0 Обзор: совместимость аннотаций и форматов

#### Какие типы экспортирует каждый формат

| Тип аннотации | Detect | Segment | OBB | Pose | Point | Classify |
|--------------|:------:|:-------:|:---:|:----:|:-----:|:--------:|
| **BBOX** | ✓ | ✓ → полигон | — | — | — | — |
| **POLYGON / SEGMENT** | ★ | ✓ | — | — | — | — |
| **POLYLINE** | ★ | ✓ | — | — | — | — |
| **MASK** | ★ | ✓ → контур | — | — | — | — |
| **OBB** | — | — | ✓ | — | — | — |
| **POSE (keypoints)** | — | — | — | ✓ | — | — |
| **POINT** | — | — | — | — | ✓ | — |
| **CLASSIFICATION** | — | — | — | — | — | ✓ |

★ — только при `geometry_policy = Convert`; при `Skip` (по умолчанию) — игнорируется.

#### Формат строки в label-файле

| Формат | Строка | Примечание |
|--------|--------|------------|
| **Detect** | `cls cx cy w h` | нормализованные [0, 1] |
| **Segment** | `cls x1 y1 x2 y2 … xn yn` | произвольное кол-во вершин |
| **OBB** | `cls x1 y1 x2 y2 x3 y3 x4 y4` | 4 угла TL→TR→BR→BL (8 чисел) |
| **Pose** | `cls cx cy w h  kx1 ky1 v1  kx2 ky2 v2 …` | v: 0=невидим, 2=виден; bbox авто из keypoints + 5% отступ |
| **Point** | `cls cx cy 0.01 0.01  x y 2` | 1-keypoint pose; синтетический bbox 1% |
| **Classify** | — (нет labels/) | папочная структура `<split>/<class_name>/img.jpg` |

#### Как Detect конвертирует чужие типы (Convert-policy)

| Тип | Результат |
|-----|-----------|
| POLYGON / SEGMENT | bounding box вершин → `cx cy w h` |
| POLYLINE | bounding box вершин → `cx cy w h` |
| MASK | bbox из метаданных (`ann.data["bbox"]`) → `cx cy w h` |

---

### 7.1 YOLO Detect +
**Формат:** `class_id  cx  cy  w  h` (нормализованные [0,1])

**Пример `labels/train/img1.txt`:**
```
0 0.512 0.342 0.234 0.156
1 0.720 0.510 0.180 0.210
```

**Пример `data.yaml`:**
```yaml
path: C:/dataset
train: images/train
val: images/val
nc: 2
names: ['car', 'person']
```

---

### 7.2 YOLO Segment +
**Формат:** `class_id  x1 y1  x2 y2  ...  xn yn`

**Пример `labels/train/img1.txt`:**
```
0 0.234 0.156 0.456 0.134 0.678 0.156 0.580 0.310 0.234 0.310
```
> **BBOX** → конвертируется в полигон из 4 угловых точек TL→TR→BR→BL: итого **8 чисел**.  
> **MASK** → экспортируется как контур маски (полигон из `ann.data["polygon"]`).  
> **POLYLINE** → экспортируется как есть (вершины полилинии).  
> **OBB / POSE / POINT / CLASSIFY** — игнорируются.

---

### 7.3 YOLO OBB +
**Формат:** `class_id  x1 y1  x2 y2  x3 y3  x4 y4` (4 угла повёрнутого прямоугольника)

**Пример `labels/train/img1.txt`:**
```
0 0.234 0.156 0.456 0.134 0.480 0.290 0.258 0.312
```

---

### 7.4 YOLO Pose +
**Формат:** `class_id  cx cy w h  kx1 ky1 v1  kx2 ky2 v2  ...`  
`v`: 0 = не размечена, 2 = видима  
bbox = авто-вычисляется из видимых точек + 5% отступ

**Пример `labels/train/img1.txt` (3 keypoints):**
```
0 0.512 0.342 0.180 0.210 0.500 0.290 2 0.480 0.310 2 0.530 0.308 2
```

**Пример `data.yaml` (с kpt_shape):**
```yaml
path: C:/dataset
train: images/train
val: images/val
nc: 1
names: ['person']

kpt_shape: [3, 3]
```

---

### 7.5 COCO Instances +
**Формат:** JSON per split; атрибуты включены; bbox в пикселях `[x, y, w, h]`

**Пример `annotations/instances_train.json`:**
```json
{
  "info": {"version": "1.0", "description": "Exported by Annotator"},
  "licenses": [],
  "categories": [
    {"id": 0, "name": "car",    "supercategory": ""},
    {"id": 1, "name": "person", "supercategory": ""}
  ],
  "images": [
    {"id": 1, "file_name": "img1.jpg", "width": 1920, "height": 1080}
  ],
  "annotations": [
    {
      "id": 1,
      "image_id": 1,
      "category_id": 0,
      "segmentation": [[234, 168, 438, 144, 652, 168, 558, 334, 225, 334]],
      "bbox": [225, 144, 427, 190],
      "area": 38430,
      "iscrowd": 0,
      "attributes": {"damage": "heavy"}
    }
  ]
}
```

> Атрибуты класса (если заданы) попадают в поле `"attributes": {...}` каждой аннотации.

---

### 7.6 COCO Keypoints +
**Формат:** JSON per split; keypoints в пикселях `[x y v  x y v  ...]`  
`v`: 0 = отсутствует, 2 = видима  
bbox авто-вычисляется из видимых точек + 5% от размера изображения

**Пример `annotations/keypoints_train.json`:**
```json
{
  "categories": [
    {
      "id": 4,
      "name": "person",
      "supercategory": "",
      "keypoints": ["nose", "left_eye", "right_eye"],
      "skeleton": [[0, 1], [0, 2]]
    }
  ],
  "images": [
    {"id": 0, "file_name": "img1.jpg", "width": 1920, "height": 1080}
  ],
  "annotations": [
    {
      "id": 0,
      "image_id": 0,
      "category_id": 4,
      "keypoints": [487.07, 530.17, 2, 387.93, 729.88, 2, 574.35, 731.32, 2],
      "num_keypoints": 3,
      "bbox": [291.93, 476.17, 378.42, 309.71],
      "area": 116978.0,
      "iscrowd": 0
    }
  ]
}
```

> Экспортирует только POSE-аннотации; остальные типы игнорируются.  
> `skeleton` в категории — рёбра 0-indexed, как в схеме классов.  
> Если точка не размечена (v=0), координаты `x=0 y=0`.

### 7.8 YOLO Point +
**Формат:** YOLO 1-keypoint pose с синтетическим bbox 1%  
`class_id  cx cy 0.01 0.01  x y 2`

**Пример `labels/train/img1.txt`:**
```
0 0.512 0.342 0.010 0.010 0.512 0.342 2
```

**Пример `data.yaml`:**
```yaml
nc: 1
names: ['crack_center']
kpt_shape: [1, 3]
```

### 7.9 YOLO Classify +

### 7.10 Multi-task (общий images/, несколько форматов) +

**Используем:** File → Export Dataset → режим **Multi-task**  
**Выбираем:** любую комбинацию чекбоксов; политику несовместимых типов  
**Получаем** (при всех 5 чекбоксах):
```
<output>/
  images/
    train/   val/              ← изображения скопированы один раз (для detect/seg/obb/pose)
  labels_detect/
    train/   val/              ← bbox-файлы
  labels_segment/
    train/   val/              ← polygon-файлы
  labels_obb/
    train/   val/              ← OBB-файлы (4 угла)
  labels_pose/
    train/   val/              ← keypoint-файлы
  classify/
    train/
      <class_name>/            ← изображения для classify (свои копии)
    val/
      <class_name>/
  data_detect.yaml
  data_segment.yaml
  data_obb.yaml
  data_pose.yaml               ← включает kpt_shape
```

> **Classify** выгружается в отдельную папку `classify/` — у него другая структура (папки по классам вместо labels/*.txt), поэтому `images/` он не использует.

**Пример `data_detect.yaml`:**
```yaml
# Multi-task export — images shared at images/{split}/
# Labels at labels_detect/{split}/
path: C:/exports/run1
train: images/train
val: images/val
label_dir: labels_detect
nc: 2
names: ['car', 'person']
```

**Пример `data_pose.yaml`** (с kpt_shape):
```yaml
# Multi-task export — images shared at images/{split}/
# Labels at labels_pose/{split}/
path: C:/exports/run1
train: images/train
val: images/val
label_dir: labels_pose
nc: 1
names: ['person']
kpt_shape: [3, 3]
```

#### Доступные чекбоксы в Multi-task

| Чекбокс | Папка с лейблами | yaml-файл | Примечание |
|---------|-----------------|-----------|------------|
| YOLO Detect | `labels_detect/` | `data_detect.yaml` | affected by geometry_policy |
| YOLO Segment | `labels_segment/` | `data_segment.yaml` | — |

| YOLO Classify | `classify/` | нет yaml | отдельная папочная структура |

#### Политика несовместимых типов (`geometry_policy`)

| Политика | Поведение при YOLO Detect |
|----------|--------------------------|
| **Skip** (по умолчанию) | Экспортирует только BBOX-аннотации; MASK/POLYGON/OBB/POSE игнорируются |
| **Convert** | BBOX → как обычно; MASK → bbox из `ann.data["bbox"]`; POLYGON → bounding box из вершин |

> Для Segment, OBB, Pose и Classify политика не влияет — каждый экспортёр обрабатывает только свой тип.

1. **ML → Настройки ML…** → раздел «SAM — разметка кликами» → «Обзор…» → `sam2.1_b.pt` → OK.
2. Выбрать класс `polygon`, нажать `I` (или кнопку **✧ SAM** на панели инструментов).
3. Кликнуть левой кнопкой по объекту.

**Получаем:**
- после «Загрузить» в настройках — зелёная строка «SAM готов · cuda: NVIDIA GeForce RTX 5060 Ti · … с»;
- при включении инструмента внизу подсказка, через секунду «SAM готов — кликните по объекту»;
- после клика почти сразу — маска-превью в цвете класса и зелёная точка; внизу «SAM: качество 0.9x · ~20 мс — Enter, чтобы принять».

### 14.2 Уточнение и принятие
**Делаем:**
1. После левого клика (14.1) кликнуть правой кнопкой по лишнему — соседнему объекту или фону, который попал в маску.
2. Протянуть мышью рамку вокруг объекта.
3. `Backspace` два раза, затем `Esc`.
4. Снова клик по объекту → `Enter`. Затем `Ctrl+Z`, `Ctrl+Y`.

**Получаем:**
- шаг 1: красная точка, маска убирает лишнее; шаг 2: пунктирная рамка, маска по рамке;
- шаг 3: `Backspace` убирает рамку, потом красную точку (маска пересчитывается); `Esc` убирает всё;
- шаг 4: в панели «Аннотации» новый полигон **без** 🤖, внизу «SAM: добавлено в «…»»; `Ctrl+Z` убирает его одним шагом, `Ctrl+Y` возвращает.

| Проверка | Ожидание |
|----------|----------|
| Класс `mask` → клик → Enter | маска кистью (её можно дорисовать кистью `M`) |
| Класс `bbox` → клик → Enter | рамка вокруг объекта |
| Класс `obb` → клик по наклонному объекту → Enter | **повёрнутая** рамка, плотно по объекту |
| Начать с правого клика (без левого) → Enter | только красная точка, маски нет, внизу подсказка «сначала левый клик…»; Enter ничего не добавляет |
| Класс `keypoints` → клик | ничего не происходит, внизу подсказка выбрать другой класс |
| Быстро 4–5 кликов подряд | маска обновляется по всем кликам, ничего не «залипает» |
| Клик → перейти на другое изображение (`D`) | точки и маска исчезли; на новом снимке первый клик тоже быстрый |
| Сменить класс, пока инструмент SAM активен | инструмент остаётся SAM (не переключается на Polygon/Brush) |
| Очистить путь к SAM в настройках → клик | открывается выбор файла модели |
| ML-сервер не настроен (пустой Python) → клик | внизу ошибка «not_configured …», программа работает |

## 15. SAM по рамкам (фаза 7-D)

**Подготовка:** как в разделе 14 (ML-сервер + `D:\Model\sam2.1_b.pt`); детектор `D:\Model\yolo11m.pt` (или свой `D:\Bbox_search\best.pt`).

### 15.1 Предразметка детектором с контурами SAM
**Делаем:**
1. Проект с классами `person [polygon]`, `bus [mask]`, `car [bbox]`.
2. **ML → Разметить датасет моделью…** → `yolo11m.pt` → сопоставить person, bus, car.
3. В «Параметрах» включить **«Контуры через SAM»** → **Текущее изображение**.

**Получаем:**
- галочка доступна только для модели-детектора (для `yolo11n-seg.pt` она серая);
- люди — полигоны по фигуре, автобус — маска по форме, машины — обычные рамки;
- итог «… добавлено аннотаций — N, из них обведено SAM — M»;
- `Ctrl+L` дальше тоже обводит через SAM (настройка запоминается).

### 15.2 Рамки → контуры
**Делаем:**
1. Нарисовать несколько рамок класса `car [bbox]` на 2–3 изображениях.
2. **ML → Рамки → контуры через SAM…** → «Рамки класса» `car`, «→ контуры в класс» оставить «+ новый класс «car_polygon»», «Все изображения» → **Обвести**.
3. Запустить ещё раз то же самое.
4. В «→ контуры в класс» выбрать «+ новый класс «car_mask»», включить «Удалить обведённые рамки», «Текущее изображение» → **Обвести**.

**Получаем:**
- шаг 2: появился класс `car_polygon`, на каждом изображении — полигоны по машинам с 🤖 (уверенность — оценка SAM); рамки на месте; итог «изображений с рамками — …, добавлено контуров — …»;
- шаг 3: «добавлено контуров — 0» — уже обведённые рамки пропущены;
- шаг 4: маски `car_mask` на текущем изображении, рамки `car` на нём удалены; `Ctrl+Z` возвращает всё одним шагом.

| Проверка | Ожидание |
|----------|----------|
| Рамки класса `car`, по умолчанию «→ в класс» | класс с именем `car…`, иначе «+ новый класс», **не** посторонний класс |
| Класс-цель типа `obb` | плотные повёрнутые рамки по машинам |
| Нет классов `bbox`/`obb` в проекте | подсказка «обводить нечего», кнопка «Обвести» неактивна |
| Закрыть окно во время обводки | работа останавливается, сделанное остаётся |
| Предразметка детектором: «+ новый класс» в строке | варианты bbox / polygon / mask / obb; выбран polygon при выключенной «Контуры через SAM» — оранжевая подсказка под галочкой |
| Schema → класс без разметки (например, только что созданный из модели) | тип можно сменить в выпадающем списке; у класса с разметкой — текст, подсказка «… annotation(s)» |
| Schema → удалить класс с разметкой → Reassign | в списке только классы того же типа |

## 16. Приёмка предразметки (фаза 8-A)

Подготовка: проект с 4–6 изображениями, размеченными моделью (раздел 13: **Предразметка датасета** → «Все изображения»), плюс 1–2 изображения без разметки и пара ручных рамок где-нибудь.

### 16.1 Как выглядит непроверенное
**Делаем:**
1. Открыть изображение с предразметкой.
2. Навести мышь на строку с 🤖 в панели «Аннотации».

**Получаем:**
- на холсте аннотации модели — **пунктиром**, заливка бледнее, у подписи значок 🤖; ручные — сплошной линией;
- в панели строки модели **оранжевые**, «🤖 0.87»; в заголовке «Аннотации (N) · 🤖 не проверено: K»;
- подсказка: имя модели, уверенность, «Не проверено — R принимает, правка тоже принимает»;
- в списке изображений у каждого изображения с предразметкой — **🤖K**.

### 16.2 Принять, править, отменить
**Делаем:**
1. Выделить аннотацию модели → `R`.
2. `Ctrl+Z`, затем снова `R`.
3. Другую аннотацию модели сдвинуть мышью (инструмент Select).
4. Третью удалить `Delete`.
5. Принятую выделить → **Приёмка → Вернуть выделенную в непроверенные**.

**Получаем:**
- шаг 1: линия стала сплошной, в панели «✓🤖 0.87» обычным цветом, в подсказке «Проверено: <ваше имя>» (если имя задано в **Файл → Ваше имя…**); счётчики 🤖 в заголовке и в списке изображений уменьшились; в строке состояния «Принято: 1»;
- шаг 2: `Ctrl+Z` вернул пунктир, `R` снова принял;
- после каждого `R` выделение переходит на следующую непроверенную аннотацию ниже по списку; стрелки ↑↓ в панели продолжают с текущей строки (не прыгают на первую);
- шаг 3: сдвинутая аннотация тоже стала сплошной (правка = приёмка); `Ctrl+Z` возвращает и место, и пунктир **одним** шагом;
- шаг 5: снова пунктир и 🤖.

### 16.3 Проход по датасету
**Делаем:**
1. Встать на изображение **без** предразметки → `U`.
2. `Shift+R`.
3. Повторять `Shift+R`, пока не кончится.
4. `R` без выделенной аннотации.

**Получаем:**
- шаг 1: открылось следующее изображение с 🤖;
- шаг 2: всё на нём принято, программа сама перешла к следующему изображению с 🤖 («Принято: N»);
- шаг 3: на последнем — «Среди показанных изображений непроверенных 🤖-аннотаций не осталось», изображение не меняется; в списке ни одного 🤖;
- шаг 4: подсказка «Сначала выделите 🤖-аннотацию (Shift+R принимает всё изображение)».

### 16.4 Фильтр, QC, экспорт, повторная предразметка
Сначала снова сделать немного непроверенного: **ML → Разметить текущее изображение моделью** (`Ctrl+L`) на 1–2 изображениях.

| Проверка | Ожидание |
|----------|----------|
| Список изображений → второй выпадающий список → **🤖 Не проверено** | только изображения с 🤖; `U` / `Shift+R` ходят по ним |
| QC → **Validate** | в статистике строка **🤖 Review: принято / всего · не проверено: K (M img)**; в списке проблем ℹ «N unreviewed model annotation(s)» на каждое такое изображение; двойной клик — переход и выделение |
| **Файл → Экспорт датасета…** | галочка **Skip unreviewed 🤖 annotations (K on M images)**, выключена; если всё принято — галочки нет |
| Экспорт YOLO Detect с галочкой и без | с галочкой в `.txt` нет строк непроверенных аннотаций, принятые и ручные на месте |
| На изображении с принятыми и непроверенными — `Ctrl+L` | непроверенные заменены новыми, **принятые (✓🤖) и ручные остались** |
| **ML → Удалить разметку модели…** | считает и удаляет только непроверенные; ✓🤖 остаются |
| **Файл → Настройки проекта → Hotkeys** | строки «Review: accept selected / accept image → next / next image to review»; переназначить `R`, проверить, что новая клавиша работает |
| Закрыть и открыть проект | статус «принято» сохранился |

## 17. Видео и треки (фаза 8-B)

Подготовка: любое короткое видео (10–30 с) с движущимися объектами — машины на дороге, люди, видео с телефона. Новый проект или существующий.

### 17.1 Импорт
**Делаем:**
1. **Файл → Импорт видео…** → выбрать видео.
2. Посмотреть сведения под полем и оценку «≈ N кадров»; поменять «Брать каждый» и «С — по» — оценка меняется.
3. Вернуть шаг по умолчанию → **Импортировать**.
4. Ещё раз импортировать то же видео, на середине нажать **Стоп**.
5. Перетащить файл видео мышью в список изображений.

**Получаем:**
- шаг 1: размер, к/с, число кадров, длительность; шаг по умолчанию ≈ 5 кадров на секунду; папка `<видео>_frames` рядом с папкой проекта;
- шаг 3: прогресс, затем окно закрывается и открывается первый кадр; в списке — `<видео>_000000.jpg`, `<видео>_000005.jpg`… по порядку; под холстом — **лента кадров**; `A` / `D` листают кадры;
- шаг 4: часть кадров добавлена; код видео — с `_2`, файлы не пересекаются с первым импортом;
- шаг 5: открывается окно импорта с этим видео.

### 17.2 Лента кадров
| Проверка | Ожидание |
|----------|----------|
| Строка на ленте | «🎞 имя.mp4 · кадр 120 · 00:04.80 · 25 / 150» — номер кадра в видео и время совпадают с видео |
| Клик и протяжка по полосе | переход к кадру, белая линия идёт за мышью |
| Кнопки ◀ ▶ | соседние кадры |
| Обычное изображение (не из видео) | ленты нет |
| Кадры с разметкой | серые отметки на полосе |

### 17.3 Трек с интерполяцией
**Делаем:**
1. На первом кадре обвести машину рамкой → выделить → **`T`**.
2. Перейти на 10–20 кадров вперёд → **`Shift+T`** → перетащить появившуюся рамку **за середину** на машину (углы — подогнать размер).
3. Пролистать кадры между ними (`A` / `D`).
4. Ещё дальше → `Shift+T` → подвинуть. Затем на промежуточном кадре чуть сдвинуть рамку.
5. `Ctrl+Z`, потом `Ctrl+Y`.
6. На последнем ключевом кадре удалить рамку (`Delete`), затем `Ctrl+Z`.
7. `Shift+A` / `Shift+D` несколько раз.

**Получаем:**
- шаг 1: подпись `car #1◆`, в панели «· #1◆»; на ленте справа «Трек #1 car · ◆ 1», ромб на полосе; инструмент переключился на **Select**;
- шаг 2: на всех кадрах между ключевыми — рамки `car #1` (без ◆), плавно идущие за машиной; на полосе — цветная полоса трека и два ромба;
- шаг 4: сдвинутый промежуточный кадр стал ключевым (◆), соседние кадры подстроились под него;
- шаг 5: промежуточные кадры возвращаются и снова меняются вместе с ключевым;
- шаг 6: трек заканчивается на предыдущем ключевом кадре (дальше рамок нет); `Ctrl+Z` возвращает всё;
- шаг 7: переход по ключевым кадрам трека.

| Проверка | Ожидание |
|----------|----------|
| Трек из полигона (класс polygon), на втором ключевом кадре — другое число вершин | промежуточные полигоны плавно перетекают |
| OBB, повёрнутая на втором ключевом кадре | промежуточные поворачиваются по кратчайшему пути |
| Выделить аннотацию другого трека | на ленте активный трек меняется |
| `T` на маске кистью / на обычном изображении | подсказка в строке состояния, трек не создаётся |
| Select: тянуть любую рамку / полигон за середину | аннотация переезжает целиком, за край изображения не выходит; простой клик (без сдвига) ничего не двигает; `Ctrl+Z` — назад |
| **Видео → Удалить активный трек…** | вопрос с числом кадров; трек исчезает со всех кадров |
| Предразметка YOLO на кадрах видео, приёмка `R` | работают как на обычных изображениях |
