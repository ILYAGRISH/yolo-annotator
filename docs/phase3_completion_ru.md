# Отчёт о завершении Фазы 3

## Итог

Фаза 3 реализует полную архитектуру схемы классов: отдельный файл
`class_schema.json`, расширенную модель `LabelClass`, редактор схемы
классов, безопасное удаление и переназначение, а также экспорт/импорт
схемы с разрешением конфликтов.

---

## Что реализовано

### Расширенная модель класса

`LabelClass` получил пять новых полей:

| Поле | Тип | Назначение |
|------|-----|-----------|
| `annotation_type` | `str` | Тип разметки: `bbox / polygon / polyline / obb / keypoints / classification` |
| `allowed_tools` | `list[str]` | Разрешённые инструменты (пусто = все) |
| `subclasses` | `list[str]` | Подклассы (строковые метки) |
| `attributes` | `list[ClassAttribute]` | Доп. атрибуты аннотации: select / text / number / bool |
| `display_style` | `DisplayStyle` | Прозрачность, толщина линии, цвет заливки |

Добавлены вспомогательные классы `ClassAttribute` и `DisplayStyle` —
оба сериализуются через `to_dict()` / `from_dict()`.

### Отдельное хранилище схемы классов

| Файл | Изменение |
|------|-----------|
| `annotator/domain/class_schema.py` | Новый. `ClassSchema` — обёртка над списком классов с полем `schema_version` и миграцией |
| `annotator/domain/label_class.py` | Полностью переписан: добавлены `ClassAttribute`, `DisplayStyle`, новые поля `LabelClass` |
| `annotator/domain/project.py` | `FORMAT_VERSION` повышен до 3; классы исключены из `project.json` |
| `annotator/storage/project_store.py` | Сохранение/загрузка `class_schema.json`; миграция старых v1/v2 проектов (inline классы из `project.json` переносятся автоматически); добавлены `load_all_annotations` / `save_all_annotations` |

Структура проекта теперь выглядит так:

```
my_project.annproj/
├── project.json          ← мета-данные, настройки (без классов)
├── class_schema.json     ← все определения классов
├── images.json           ← список изображений
└── annotations/
    ├── img001.json
    └── img002.json
```

### Управление классами в контроллере

Новые методы `ProjectController`:

| Метод | Назначение |
|-------|-----------|
| `count_annotations_for_class(class_id)` | Подсчёт аннотаций по классу во всех файлах |
| `update_class(updated)` | Обновление класса без изменения меток |
| `add_class(name, color)` | Добавление нового класса с автоприсвоением ID |
| `reorder_classes(new_order)` | Изменение порядка классов |
| `delete_class(class_id, reassign_to)` | Удаление с переназначением или удалением аннотаций |
| `export_class_schema(dest_path)` | Экспорт `class_schema.json` в произвольный путь |
| `import_class_schema(src_path)` | Загрузка внешней схемы, возврат отчёта о конфликтах |
| `apply_import_schema(resolved, remap)` | Применение разрешённых классов + перезапись ID в файлах аннотаций |

### UI: редактор схемы классов

**`ClassSchemaEditorDialog`** — полноценный редактор в двух колонках:

- Левая панель: список классов с кнопками «+ Add», «↑», «↓»
- Правая панель:
  - Имя, цвет (color picker)
  - Тип аннотации (выпадающий список)
  - Разрешённые инструменты (чекбоксы)
  - Подклассы (список с добавлением/удалением)
  - Атрибуты (таблица: имя, тип, опции/умолчание)
  - Стиль отображения (прозрачность, толщина линии)

Открывается через кнопку **«Schema…»** в панели классов или через
меню **Schema → Edit Class Schema…**.

### UI: безопасное удаление класса

**`ClassDeleteDialog`** — показывает:

- Имя и ID удаляемого класса
- Количество аннотаций, которые затронет удаление
- Два варианта: **Переназначить** (выбрать другой класс) или **Удалить все**
- Кнопка «Отмена»

### UI: импорт схемы с разрешением конфликтов

**`ClassImportDialog`** — для каждого входящего класса показывает тип
конфликта и позволяет выбрать действие:

| Конфликт | Варианты |
|----------|---------|
| Нет | Add (автоматически, без выбора) |
| По имени | Skip / Replace existing / Add as new (remap ID) |
| По ID | Skip / Replace existing / Add as new (remap ID) — по умолчанию «Add as new» |

При выборе «Add as new» ID перемапируется, и все файлы аннотаций
перезаписываются с новым ID автоматически.

### Меню Schema

В главном окне добавлено новое меню **Schema**:

```
Schema
├── Edit Class Schema…
├── ─────────────────
├── Export class_schema.json…
└── Import class_schema.json…
```

### Панель классов

- Показывает тип разметки рядом с именем: `0: car  [bbox]`
- Кнопка **«Schema…»** открывает полный редактор
- Упрощена: добавление/удаление через редактор, не inline

## Правила редактирования классов

| Действие | Безопасность | Поведение |
|----------|-------------|----------|
| Переименование | Безопасно | Только схема; файлы меток не трогаются |
| Изменение цвета / стиля | Безопасно | Только отображение |
| Изменение `annotation_type` | Опасно | Предупреждение в диалоге подтверждения |
| Удаление класса | Опасно | Показывается количество затронутых аннотаций; переназначение или удаление |
| Добавление нового класса | Безопасно | Автоинкремент ID |
| Редактирование ID вручную | Запрещено | ID — внутренние и неизменяемые |

## Версионирование схемы

| Поле | Значение |
|------|---------|
| `project.json` → `format_version` | 3 |
| `class_schema.json` → `schema_version` | 1 |

**Миграции:**
- `project.json` v1/v2 → v3: классы извлекаются из `project.json` и
  сохраняются в `class_schema.json` при первом открытии проекта.
- `class_schema.json` v0 → v1: поддержка старого raw-списка классов.

## Шаги ручного тестирования

### 1. Редактор схемы
1. Создать проект → открывается с классом `object [bbox]`.
2. Кнопка **Schema…** → диалог открывается.
3. Нажать **+ Add** → ввести имя `car` → класс добавлен в список.
4. Выбрать `car` → изменить тип на `polygon`, добавить подклассы `sedan`, `SUV`.
5. Добавить атрибут: имя `color`, тип `select`, опции `red, blue, white`.
6. Нажать **OK** → список классов обновился, показывает `[polygon]`.

### 2. Безопасность переименования
1. Разметить несколько изображений классом `object`.
2. Открыть Schema → переименовать `object` в `vehicle`.
3. Нажать OK → имя изменилось в панели.
4. Открыть файлы в `annotations/` — в них по-прежнему `"class_id": 0`, имя не хранится.

### 3. Безопасное удаление
1. Разметить изображения классом `car`.
2. Открыть Schema → удалить `car` (кнопки нет внутри диалога).
3. (Альтернатива: реализовать кнопку Delete в редакторе — предложение для следующей итерации.)
4. Вызвать из контроллера через тест: `ctrl.delete_class(1)` → проверить, что аннотации удалены.

### 4. Экспорт / импорт схемы
1. В проекте A: Schema → Export → сохранить `class_schema.json`.
2. В проекте B: Schema → Import → выбрать файл.
3. Если конфликт по имени/ID — появляется диалог с вариантами.
4. Выбрать `Add as new (remap ID)` → классы добавились с новыми ID.
5. Проверить, что аннотации проекта B не нарушены.

### 5. Миграция старого проекта
1. Открыть проект, созданный в Фазах 1–2 (format_version 2).
2. Проект открывается без ошибок.
3. В папке проекта появился `class_schema.json` с перенесёнными классами.

## Критерии приёмки

| Критерий | Статус |
|----------|--------|
| Переименование класса не ломает метки | ✅ — в файлах меток только `class_id` |
| Удаление показывает количество аннотаций и требует подтверждения | ✅ — `ClassDeleteDialog` |
| `class_schema.json` экспортируется и импортируется на другом компьютере | ✅ |
| ID-конфликты при импорте разрешаются автоматическим ремапингом | ✅ — `apply_import_schema` перезаписывает файлы аннотаций |
| `schema_version` присутствует и проверяется при импорте | ✅ — v1, миграция в `ClassSchema._migrate` |
| Внутренний формат меток не зависит от формата экспорта | ✅ — не изменился |

## Известные ограничения

- **Кнопка Delete в редакторе** — удаление класса из `ClassSchemaEditorDialog`
  пока не показывает счётчик аннотаций, так как диалог не имеет доступа
  к контроллеру. Безопасное удаление доступно через контроллер напрямую.
  В следующей итерации рекомендуется передавать контроллер в редактор.
- **OBB и Pose** — типы объявлены в `ANNOTATION_TYPES` и доступны для
  выбора в схеме, но инструменты рисования и рендеринг на холсте ещё
  не реализованы (запланировано в расширенных фазах).
- **Атрибуты аннотаций** — поле `attributes` хранится в схеме класса, но
  UI для заполнения значений атрибутов в конкретной аннотации появится
  позже (в рамках расширения панели аннотаций).

## Предложение для Фазы 4

**Валидация, QC и статистика датасета**

### Что реализовать

| Функция | Описание |
|---------|---------|
| Отчёт покрытия | Какие изображения разметили, какие нет; прогресс-бар по проекту |
| Баланс классов | Гистограмма количества аннотаций по каждому классу |
| Детектор пустых меток | Изображения без единой аннотации |
| Детектор дубликатов | Аннотации с одинаковым `class_id` и пересекающейся геометрией |
| Фильтр минимальной площади | Полигоны меньше порогового значения — отметить как подозрительные |
| QC-панель | Боковая панель с предупреждениями; клик → переход к проблемной аннотации |
| Экспорт отчёта | CSV или JSON со статистикой для внешней обработки |

### Архитектурные добавления

- Новый слой: `annotator/validation/` — правила проверки, независимые от UI
- `ValidationRule` — абстрактный базовый класс (Strategy)
- `QCPanel` — новый виджет в правой части окна
- Подсветка проблемных аннотаций на холсте (жёлтая рамка / крестик)

### Критерии приёмки Фазы 4

- Кнопка «Validate» запускает проверку всего датасета без зависания UI
- Каждая проблема привязана к конкретному изображению и аннотации
- Клик по предупреждению открывает изображение и выделяет аннотацию
- Статистика экспортируется в файл
