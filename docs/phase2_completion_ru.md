## Логика папки labels/

При каждом сохранении аннотаций для изображения рядом автоматически
создаётся файл `.txt` в папке `labels/`.

| Расположение изображений | Куда идут `.txt` файлы |
|---|---|
| `.../dataset/images/img.jpg` | `.../dataset/labels/img.txt` |
| `.../myfolder/img.jpg` | `.../myfolder/labels/img.txt` |

Папка `images/` (а также `imgs/`, `img/`, `photos/`) распознаётся автоматически —
`labels/` создаётся рядом с ней, а не внутри. Во всех остальных случаях `labels/`
создаётся внутри папки с изображениями.

### Формат строк в .txt файле

| Тип аннотации | Формат строки |
|---|---|
| SEGMENT | `class_id  x1 y1 x2 y2 ... xn yn` |
| POLYLINE | `class_id  x1 y1 x2 y2 ... xn yn` |
| BBOX | `class_id  x1 y1 x2 y2 x3 y3 x4 y4` (4 угла: TL → TR → BR → BL) |

Все координаты нормализованы в диапазоне [0, 1]. Пустой файл означает
отсутствие аннотаций для данного изображения (удаление аннотаций тоже отражается).

## Когда происходит экспорт

- При переходе на другое изображение (автофлаш).
- При сохранении проекта (Ctrl+S).
- При закрытии окна.
- По таймеру автосохранения (каждые 60 секунд).

Результат экспорта отображается в строке статуса:
`Saved  ·  YOLO: labels/img001.txt`

## Версионирование схемы

`project.json` теперь содержит `"format_version": 2`. При открытии файлов
старого формата (версия 1) автоматически применяется миграция. Это обеспечивает
обратную совместимость для всех проектов, созданных в Фазе 1.

## Шаги ручного тестирования

1. Создать проект, добавить изображения из папки.
2. Разметить несколько изображений (полигон, bbox, ломаная).
3. Нажать Ctrl+S — в строке статуса появится `Saved  ·  YOLO: labels/...`.
4. Открыть папку с изображениями: убедиться, что рядом создалась папка `labels/`.
5. Открыть `.txt` файл и проверить формат строк.
6. Удалить аннотацию, снова сохранить — убедиться, что строка исчезла из `.txt`.
7. Добавить новый класс через панель классов (кнопка «+») — проект сохраняется автоматически.
8. Закрыть и снова открыть проект — классы и аннотации сохранены.
9. Подождать 60 секунд — автосохранение срабатывает без каких-либо действий.

## Известные ограничения

- BBOX экспортируется как 4-угольный полигон (не как `cx cy w h`). Это правильный
  формат для задачи `yolo task=segment`, но не подходит для `yolo task=detect`.
  Для detection-экспорта нужен отдельный профиль (Фаза 5).
- Таймер автосохранения фиксирован на 60 секунд. Настройка через
  `ProjectSettings.autosave_interval_sec` будет подключена в Фазе 5
  (после появления UI настроек).
- Миграция схемы v1→v2 не изменяет данные, только добавляет `settings` по
  умолчанию. Более сложные миграции понадобятся начиная с Фазы 3.

## Предложение для Фазы 3

**Расширение типов аннотаций: OBB / Pose / Classify**

- **OBB** (oriented bounding box) — инструмент рисования поворачиваемого
  прямоугольника, `OBBAnnotationItem`, экспорт в формат YOLO OBB.
- **Pose / скелет** — инструмент расстановки ключевых точек, редактор
  шаблона скелета, экспорт в формат YOLO Pose.
- **Classify** — метка на уровне изображения без геометрии.
- Обновление YOLO-экспортёра для каждого нового типа.

Фаза 3 завершит поддержку всех базовых типов разметки YOLO.
