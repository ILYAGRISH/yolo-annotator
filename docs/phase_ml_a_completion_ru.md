# Фаза 7-A — инфраструктура ML-сервера: отчёт

## Итог

Основа для функций с нейросетями (Phase 7 роадмапа). Модели работают в **отдельном процессе** со **своим** Python-окружением; программа разметки общается с ним сообщениями JSON. Пользователь может выбрать окружение, проверить его (PyTorch, Ultralytics, GPU) и пробно загрузить YOLO-модель. Самой предразметки ещё нет — это фаза 7-B, протокол под неё уже готов.

Главное требование — **максимальная независимость от основной программы**:

| Требование | Как выполнено |
|---|---|
| Тяжёлые зависимости не попадают в программу | torch / ultralytics живут только в `.venv-ml` (или в выбранном conda-окружении); `requirements.txt` программы не изменился; программа их никогда не импортирует |
| Падение модели не роняет программу | отдельный процесс; при падении — индикатор «ошибка», ожидающие запросы получают ошибку, следующий запрос перезапускает сервер |
| Минимум изменений в основном коде | в `main_window.py` — 3 вызова: `install()` (в `try/except`), `retranslate()`, `shutdown()`. Всё остальное — в `annotator/ml/` и `ml_backend/` |
| Сломанное расширение не ломает программу | `install()` обёрнут в `try/except`: программа запускается без меню ML (есть тест) |
| Свои строки и настройки | `annotator/ml/strings.py` (EN/RU), ключи настроек `ml/...`; общий `i18n.py` не тронут |
| Ничего не работает «за спиной» | сервер не стартует, пока ML не используется (автозапуск — опция, выключен) |

## Архитектура

```
Программа (PyQt6, .venv)                     ML-сервер (.venv-ml / conda)
annotator/ml/                                ml_backend/
  extension.py  меню ML, индикатор            server.py   цикл: запрос → обработчик → ответ
  client.py     MLBackend (QProcess) ◄──────► protocol.py JSON по строке, stdin / stdout
  settings_dialog.py, config.py, strings.py   handlers/   system, debug, yolo
```

- **Транспорт:** JSON — одна строка на сообщение, stdin/stdout дочернего процесса. Без сетевых портов и брандмауэра; сервер завершается, когда закрывается его stdin (т. е. вместе с программой, даже при её падении).
- **Гарантия:** на каждый запрос — ровно один ответ (результат или ошибка с типом: `cancelled`, `not_found`, `bad_request`, `missing_package`, `exception`; на стороне клиента — `not_configured`, `start_failed`, `backend_exited`, `stopped`).
- **Длинные задачи:** события прогресса (не чаще 10 в секунду) и кооперативная отмена; задачи идут по очереди, `ping` и `cancel` отвечают сразу.
- **Асинхронность:** клиент работает в GUI-потоке на сигналах `QProcess` — интерфейс не зависает.

### Две ловушки Windows, найденные и закрытые

1. **Мусор в stdout.** Библиотеки (ultralytics, tqdm, C-код) печатают в stdout и ломают протокол. Сервер забирает себе копию stdout, а fd 1 и `sys.stdout` направляет в stderr (журнал). Тест: `debug.noisy` пишет в stdout тремя способами — протокол цел.
2. **Взаимная блокировка на stdin.** Пока поток сервера ждёт запрос на stdin, загрузка любой DLL (OpenCV, torch) в другом потоке зависала: инициализация C-рантайма DLL опрашивает стандартный ввод, а Windows ставит этот опрос в очередь за ожидающим чтением. Сервер читает запросы из **личной копии** stdin, а стандартный ввод процесса переключает на NUL (`SetStdHandle`).

## Как запустить

```bat
cd new_annotator
.venv\Scripts\python main.py                       :: программа → ML → Настройки ML…
setup_ml_env.bat                                    :: создать .venv-ml (до ~3 ГБ), если нет готового окружения
.venv\Scripts\python test_ml_backend.py             :: тесты (без PyTorch)
set ML_TEST_PYTHON=C:\miniconda3\envs\yolo_hard\python.exe
set ML_TEST_MODEL=D:\Bbox_search\best.pt
.venv\Scripts\python test_ml_backend.py             :: + проверка реальной модели на GPU
```

## Проверено

- Все наборы тестов, включая новый `test_ml_backend.py`: 61/61, с реальной моделью — 64/64.
- `yolo_hard` (Python 3.11, torch 2.11.0+cu128, ultralytics 8.4.33): RTX 5060 Ti найдена, `best.pt` (detect, 2 класса) загружается за 0,4 с, из кэша — мгновенно.
- `setup_ml_env.bat` целиком **не запускался** (готовое окружение нашлось): версии в нём взяты из проверенного `yolo_hard`. Проверить установкой с нуля — при следующем релизе.

## Риски и ограничения

- Предразметки ещё нет — только проверка окружения и модели.
- `.pt` — формат с исполняемым кодом: загружать только свои / доверенные модели (написано в About.md).
- Linux / macOS не проверялись; скрипта `.venv-ml` для Linux нет.
- Задачи выполняются строго по одной.

## Предложение: фаза 7-B — предразметка YOLO

1. `yolo.predict` в сервере: изображение(я) → боксы / полигоны / OBB / ключевые точки / класс (по типу модели), порог уверенности, размер, устройство.
2. Сопоставление классов модели и проекта: автоматически по имени + диалог ручного сопоставления, сохранение в настройках проекта.
3. Команды: «Разметить текущее изображение» (горячая клавиша) и «Разметить датасет…» (все / только неразмеченные / выбранный сплит) с прогрессом и отменой.
4. Результаты — обычные аннотации с `meta.source = "model"` и уверенностью; отмена одним шагом Ctrl+Z; фильтр/подсветка «не проверено», принятие.
5. Защита от дублей при повторном запуске.
