# О программе — YOLO Annotator

YOLO Annotator — это десктопный инструмент для разметки изображений, предназначенный для подготовки обучающих датасетов под задачи компьютерного зрения (детекция, инстанс-, семантическая и panoptic-сегментация, OBB, ключевые точки, классификация). Программа хранит данные во внутреннем формате `.annproj`, поддерживает несколько типов аннотаций, схему классов и экспорт в форматы YOLO, COCO (Instances / Keypoints / Panoptic), Pascal VOC, LabelMe и семантические маски.

---

## Типы аннотаций

| Тип | Ключ | Описание |
|-----|------|----------|
| **Bounding Box** | `bbox` | Прямоугольник, заданный центром и размерами (x, y, w, h) в нормализованных координатах. Используется для задачи детекции объектов (YOLO detect). |
| **Polygon / Segmentation** | `polygon` | Замкнутый многоугольник из произвольного числа вершин. Используется для задачи инстанс-сегментации (YOLO segment). Площадь вычисляется по формуле Гаусса (shoelace). |
| **Polyline** | `polyline` | Незамкнутая ломаная линия. Применяется для разметки дорог, границ, трубопроводов и других протяжённых объектов. |
| **OBB (Oriented Bounding Box)** | `obb` | Повёрнутый прямоугольник, заданный центром, размерами и углом поворота. Используется для детекции объектов с произвольной ориентацией (YOLO obb). |
| **Keypoints / Pose** | `keypoints` | Набор именованных точек на объекте (например, суставы тела). Используется для оценки позы (YOLO pose). |
| **Point** | `point` | Одиночная точка на изображении. Используется для подсчёта объектов, разметки центроидов, ориентиров. Экспорт — YOLO Point (1-keypoint pose). |
| **Classification** | `classification` | Метка на уровне всего изображения — без геометрии. Обозначает класс сцены или содержимого кадра. |
| **Mask (кисть)** | `mask` | Бинарная маска объекта, нарисованная кистью (Brush `M`). Каждая зафиксированная маска — отдельный объект (инстанс). |
| **Semantic (область класса)** | `semantic` | Область класса, нарисованная семантической кистью (`S`). На одном изображении у класса ровно один слой; все мазки класса сливаются в него. Используется для семантической сегментации и как «stuff» в panoptic. |

Каждый класс разметки в схеме жёстко привязан к одному типу аннотации. После создания класса тип изменить нельзя. Это гарантирует согласованность данных: один класс — один тип геометрии.

## Атрибуты классов

Каждому классу можно добавить произвольное число атрибутов — дополнительных полей, которые разметчик заполняет для каждой аннотации этого класса. Атрибуты добавляются в **Schema → Edit Class Schema → кнопка `+ Add attribute`**.

### Типы атрибутов

| Тип | Виджет при разметке | Описание |
|-----|---------------------|----------|
| **text** | Текстовое поле | Произвольная строка. Используется для идентификаторов, комментариев, свободных меток. |
| **number** | Числовое поле | Целое или дробное число. Подходит для количественных характеристик: счётчики, размеры, баллы качества. |
| **bool** | Чекбокс | Логическое значение (да / нет). Для бинарных признаков: `occluded`, `truncated`, `is_primary`. |
| **select** | Выпадающий список | Закрытый набор вариантов, задаваемых при создании атрибута. Подходит, когда нужно выбрать ровно один вариант из фиксированного списка. |

### Атрибут типа `select`

При создании атрибута типа `select` в поле **Options (comma-separated)** перечисляются допустимые варианты через запятую:

```
good, damaged, occluded
```

Во время разметки разметчик видит выпадающий список и выбирает один из заданных вариантов.

Примеры применения:

| Класс | Атрибут | Варианты |
|-------|---------|----------|
| `car` | `color` | `red, blue, white, black, other` |
| `rail` | `condition` | `good, cracked, worn` |
| `person` | `pose` | `standing, sitting, lying` |
| `sign` | `visibility` | `clear, partially_occluded, blurred` |

### Экспорт атрибутов

- **COCO JSON** — атрибуты включаются в экспорт для каждой аннотации.
- **YOLO** — атрибуты не поддерживаются форматом; при экспорте в YOLO программа выводит предупреждение, если у классов есть атрибуты.

## Управление классами — удаление

Удаление класса выполняется через **Schema → Edit Class Schema → кнопка `− Delete`** (левая панель).

### Что происходит с аннотациями

При удалении сохранённого класса программа предлагает выбор:

| Действие | Результат |
|----------|-----------|
| **Reassign to…** | Все аннотации удаляемого класса переназначаются на выбранный класс. Геометрия сохраняется. |
| **Delete all annotations** | Все аннотации удаляемого класса удаляются из всех изображений проекта. |
| **Cancel** | Удаление отменяется, класс остаётся. |

### Защиты и поведение

- **Последний класс** — удалить нельзя: схема обязана содержать хотя бы один класс.
- **Новый класс** (созданный в текущей сессии редактора, ещё не сохранённый) — удаляется молча, без диалога: аннотаций у него нет.
- **Cancel в Schema Editor** — отменяет все несохранённые изменения, включая запланированные удаления.
- Удаление применяется ко **всем файлам аннотаций** проекта — не только к текущему изображению.

## Горячие клавиши выбора класса

Цифры `0`–`9` мгновенно переключают активный класс по его ID:

- `1` — выбрать класс с ID 1
- `0` — выбрать класс с ID 0
- **Двузначные классы (10–99):** нажать две цифры подряд в течение 600 мс — например `1` затем `2` выбирает класс 12

Клавиши работают независимо от того, какой виджет активен (холст, список изображений и т.д.), и игнорируются в текстовых полях ввода.

## Авто-экспорт в YOLO (папка `labels/`)

При каждом сохранении аннотаций программа автоматически записывает файл разметки в папку `labels/` рядом с изображениями — без необходимости запускать явный экспорт.

Расположение папки:
- если изображения лежат в папке с именем `images` → `../labels/`
- иначе → `labels/` рядом с папкой изображений

### Формат авто-экспорта

Формат выбирается в **File → Project Settings → Auto-export format**:

| Значение | Поведение |
|----------|-----------|
| **Auto** (по умолчанию) | Формат определяется автоматически по типам классов в схеме: bbox→Detect, obb→OBB, keypoints→Pose, point→Point, остальное→Seg |
| **YOLO Detect** | Всегда `class cx cy w h` |
| **YOLO Segment** | Всегда полигон (bbox конвертируется в 4-угольный полигон) |
| **YOLO OBB** | Всегда 4 угловые точки |
| **YOLO Pose** | Всегда формат с кейпоинтами |
| **YOLO Point** | Всегда 1-keypoint pose |

## Разбивка датасета (Split Dataset)

**File → Split Dataset** — распределяет изображения проекта по сплитам `train` / `val` / `test`.

- Задаётся доля val (%) и test (%), train получает остаток.
- Режим **All images** — переназначает все изображения (перезаписывает существующие сплиты).
- Режим **Unassigned only** — назначает только изображения без сплита.
- Опция **Shuffle** — перемешивает изображения перед распределением.

Сплит каждого изображения хранится в `images.json` и учитывается при экспорте датасета (структура `labels/train/`, `labels/val/`, `labels/test/`).

---

## Экспорт датасета

**File → Export Dataset (Ctrl+E)** — экспортирует все изображения и аннотации проекта в выбранный формат.

### Режимы экспорта

| Режим | Описание |
|-------|----------|
| **Single format** | Один формат → одна папка `output/images/` + `labels/` + `data.yaml` |
| **Multi-task** | Несколько форматов → общая `images/`, отдельные `labels_detect/`, `labels_segment/`, ... |

### Совместимость типов аннотаций с форматами

| Тип аннотации | Detect | Segment | OBB | Pose | Point | Classify | COCO Inst. | COCO Kpt. |
|--------------|:------:|:-------:|:---:|:----:|:-----:|:--------:|:----------:|:---------:|
| **BBOX** | ✓ | ✓ → полигон | — | — | — | — | ✓ | — |
| **POLYGON / SEGMENT** | ★ | ✓ | — | — | — | — | ✓ | — |
| **POLYLINE** | ★ | ✓ | — | — | — | — | ✓ | — |
| **MASK** | ★ | ✓ → контур | — | — | — | — | ✓ полигоны / RLE | — |
| **SEMANTIC** | — | ✓ полигон на каждую область | — | — | — | — | ✓ полигоны / RLE | — |
| **OBB** | — | — | ✓ | — | — | — | ✓ | — |
| **POSE (keypoints)** | — | — | — | ✓ | — | — | — | ✓ |
| **POINT** | — | — | — | — | ✓ | — | — | — |
| **CLASSIFICATION** | — | — | — | — | — | ✓ | — | — |

★ — только при политике `Convert`; при `Skip` (по умолчанию) — игнорируется.

Форматы масок и panoptic:

| Тип аннотации | Semantic Masks | COCO Panoptic | LabelMe | Pascal VOC |
|--------------|:--------------:|:-------------:|:-------:|:----------:|
| **SEMANTIC** | ✓ из PNG (снизу) | ✓ stuff / thing по роли класса | ✓ полигон на область | — |
| **MASK** | ✓ из PNG | ✓ | ✓ контур | ✓ bbox |
| **POLYGON / SEGMENT** | ✓ | ✓ | ✓ | ✓ bbox |
| **BBOX / OBB** | ✓ заливка | ✓ заливка | ✓ | ✓ |
| **POLYLINE** | ✓ толстая линия | ✓ толстая линия | ✓ | ✓ bbox |
| **POSE / POINT / CLASSIFY** | — | — | POSE / POINT ✓ | — |

### Формат строки в label-файле

| Формат | Строка | Примечание |
|--------|--------|------------|
| **YOLO Detect** | `cls cx cy w h` | нормализованные [0, 1] |
| **YOLO Segment** | `cls x1 y1 x2 y2 … xn yn` | произвольное кол-во вершин; BBOX → 4-угловой полигон (8 чисел TL→TR→BR→BL) |
| **YOLO OBB** | `cls x1 y1 x2 y2 x3 y3 x4 y4` | 4 угла поворота TL→TR→BR→BL |
| **YOLO Pose** | `cls cx cy w h  kx1 ky1 v1  kx2 ky2 v2 …` | v: 0=невидим, 2=виден; bbox авто из keypoints + 5% отступ |
| **YOLO Point** | `cls cx cy 0.01 0.01  x y 2` | 1-keypoint pose; синтетический bbox 1% |
| **YOLO Classify** | — (нет labels/) | папочная структура `<split>/<class_name>/img.jpg` |
| **COCO Instances** | JSON `annotations/instances_<split>.json` | BBOX/POLYGON/OBB → segmentation + bbox; MASK/SEMANTIC → полигоны или RLE (опция «Masks as»); атрибуты |
| **COCO Panoptic** | JSON `annotations/panoptic_<split>.json` + PNG | сегменты things + stuff; id сегмента закодирован в цвете пикселя |
| **COCO Keypoints** | JSON `annotations/keypoints_<split>.json` | только POSE; keypoints в пикселях + skeleton в категории |

### Политика несовместимых типов для YOLO Detect (`geometry_policy`)

| Политика | Поведение |
|----------|-----------|
| **Skip** (по умолчанию) | Только BBOX-аннотации; всё остальное игнорируется |
| **Convert** | POLYGON / POLYLINE → bounding box вершин; MASK → bbox из метаданных |

### Структура выходной папки

**Single format:**
```
output/
  images/
    train/   val/   test/
  labels/
    train/   val/   test/
  data.yaml
```

**Multi-task:**
```
output/
  images/
    train/   val/              ← общие для detect/seg/obb/pose
  labels_detect/  labels_segment/  labels_obb/  labels_pose/
  classify/
    train/<class_name>/        ← отдельные копии для classify
  data_detect.yaml  data_segment.yaml  data_obb.yaml  data_pose.yaml
```

**COCO Instances / COCO Panoptic:**
```
output/
  annotations/
    instances_train.json       ← COCO Instances
    panoptic_train.json        ← COCO Panoptic
    panoptic_train/
      img001.png               ← RGB-карта сегментов
  images/
    train/   val/
```

## Многопользовательский режим (Вариант A)

Несколько разметчиков могут работать с одним проектом одновременно — каждый видит только свою часть изображений. Проект при этом находится в **общей сетевой папке** (NAS, SMB-шара).

### Роли

| Роль | Кто | Что видит |
|------|-----|-----------|
| **Лидер** | Первый открывший проект | Все изображения + тег `▸Имя` у назначенных |
| **Клиент** | Все остальные | Только свои назначенные изображения |

### Настройка (лидер)

1. Создать проект в сетевой папке (**File → New Project**).  
   При первом открытии программа спросит имя лидера — введите своё имя (например, `Илья`). Имя сохраняется и больше не запрашивается.
2. Добавить изображения (**File → Add Images from Folder…**).
3. Открыть **File → Assign Images…**:
   - Лидер уже добавлен в список пользователей автоматически.
   - Кнопка **+ Add** — добавить других разметчиков по имени.
   - Кнопка **Auto-distribute evenly** — случайно распределить все изображения поровну между всеми пользователями.
   - Или вручную: выбрать пользователя → выделить изображения в пуле «Unassigned» → **↓ Assign**.
4. Нажать **OK** — назначения сохраняются в файл `.annproj/assignments.json`.

### Работа клиента

1. Открыть ту же папку проекта (**File → Open Project…**).
2. Программа обнаруживает, что лидер — другой компьютер, и спрашивает: «Введите ваше имя».
3. Ввести имя в точности так, как лидер указал при назначении.
4. В панели **Images** появятся только свои изображения.

> Если имя не найдено в назначениях — программа закрывает проект и показывает предупреждение «обратитесь к лидеру».

### Смена имени

**File → Your Name…** — изменить отображаемое имя в любой момент. Имя хранится локально (QSettings). Если лидер переименовывается при открытом проекте, его запись в `assignments.json` обновляется автоматически.

Клиент также может сменить имя через **File → Your Name…** — при следующем открытии проекта нужно будет ввести новое имя.

### Как лидер видит прогресс

В панели **Images** у лидера каждый назначенный файл показывает тег `▸Имя` (фиолетовый цвет). Галочка `✓` появляется, когда изображение размечено. Тултип показывает «Assigned to: Имя».

### Ограничения Варианта A

- Одновременное редактирование **одного и того же изображения** двумя разметчиками не защищено — назначайте каждому уникальный набор.
- После переназначения изображений клиент должен **переоткрыть проект**, чтобы увидеть изменения.
- Лидер всегда видит все изображения, даже если часть из них назначена другим пользователям.

## Аннотация типа BBox (ограничивающий прямоугольник)

BBox (Bounding Box) — осе-ориентированный прямоугольник. Самый распространённый тип аннотации для задач детекции объектов.

### Для каких задач применяется

Детекция объектов с произвольной, но приблизительно горизонтальной ориентацией: автомобили, пешеходы, лица, животные, промышленные дефекты на фронтальных снимках.

### Рабочий процесс

1. Выбрать класс типа **bbox** в панели классов.
2. Активировать инструмент **BBox** в тулбаре (горячая клавиша `B`).
3. **Зажать ЛКМ** в одном углу объекта → **тянуть** → **отпустить** в противоположном углу.
4. **Escape** — отменить текущий прямоугольник.

Превью отображается во время рисования (жёлтый пунктирный прямоугольник). Прямоугольник слишком маленький (менее 4 px по любой стороне) игнорируется.

### Редактирование

После фиксации — выделить аннотацию инструментом Select: появляются 4 угловых хэндла для изменения размера. Весь прямоугольник можно перетащить за любую точку внутри.

### Хранение и экспорт

Хранится как `(x, y, w, h)` в нормализованных координатах, где `(x, y)` — верхний левый угол.

| Формат | Результат |
|--------|-----------|
| **YOLO Detect** | `class cx cy w h` (центр + размеры) |
| **COCO JSON** | `"bbox": [x, y, w, h]` в пикселях |
| **YOLO Segment** | bbox конвертируется в 4-угольный полигон |

## Аннотация типа OBB (повёрнутый прямоугольник)

OBB (Oriented Bounding Box) — прямоугольник с произвольным углом поворота. Позволяет точнее описать объект, который расположен не горизонтально.

### Для каких задач применяется

Аэрофотосъёмка и спутниковые снимки (самолёты, корабли, контейнеры, здания под углом), детекция текста, складские объекты с произвольной ориентацией.

### Рабочий процесс

1. Выбрать класс типа **obb**.
2. Активировать инструмент **OBB** в тулбаре.
3. **Зажать ЛКМ → тянуть → отпустить** — создаётся прямоугольник с `angle = 0°`.
4. Выделить созданную аннотацию инструментом **Select** и задать угол через хэндл поворота.
5. **Escape** — отменить во время рисования.

Превью во время рисования — оранжевый пунктирный прямоугольник.

### Редактирование угла и размера

При выделении появляются:

- **Оранжевый кружок** над верхней гранью — **хэндл поворота**: перетащить, чтобы задать угол (по часовой стрелке в экранных координатах).
- **4 белых угловых хэндла** — изменение размера (противоположный угол фиксирован).

### Хранение и экспорт

Хранится как `(cx, cy, w, h, angle_deg)` в нормализованных координатах. Угол — по часовой стрелке в системе координат экрана (ось Y вниз).

| Формат | Результат |
|--------|-----------|
| **YOLO OBB** | 4 угловые точки `x1 y1 x2 y2 x3 y3 x4 y4` |
| **COCO JSON** | Сегментационный полигон из 4 вершин |

## Аннотация типа Polygon (сегментация)

Polygon — замкнутый многоугольник с произвольным числом вершин. Описывает точный контур объекта пиксель-в-пиксель.

### Для каких задач применяется

Инстанс-сегментация: объекты неправильной формы, где bbox слишком груб — детали машин, биологические объекты, строительные конструкции, листва.

### Рабочий процесс

1. Выбрать класс типа **polygon**.
2. Активировать инструмент **Polygon** в тулбаре.
3. **ЛКМ** — добавить вершину. Первая точка отображается жёлтой, остальные белыми.
4. Замкнуть контур одним из способов:
   - **Клик на первую точку** — когда курсор в радиусе 15 px от неё, вокруг неё появляется кольцо-индикатор.
   - **Двойной клик** — зафиксировать в текущей позиции.
   - **Enter** — зафиксировать без добавления точки.
5. **ПКМ** — удалить последнюю добавленную вершину.
6. **Escape** — отменить весь контур.

Минимум 3 вершины для фиксации.

### Хранение и экспорт

Хранится как список `[[x, y], ...]` в нормализованных координатах.

| Формат | Результат |
|--------|-----------|
| **YOLO Segment** | Список нормализованных вершин |
| **COCO JSON** | `"segmentation": [[x1,y1,x2,y2,...]]` |

## Аннотация типа Polyline (ломаная линия)

Polyline — незамкнутая ломаная линия из произвольного числа вершин. В отличие от Polygon, контур не закрывается.

### Для каких задач применяется

Разметка протяжённых линейных объектов: дороги, реки, трубопроводы, кабели, границы полей, береговые линии. Если нужен буферизованный полигон (с шириной) — используйте Crack Tool.

### Рабочий процесс

1. Выбрать класс типа **polyline**.
2. Активировать инструмент **Polyline** в тулбаре.
3. **ЛКМ** — добавить вершину в конец линии.
4. Завершить: **Enter** или **двойной клик**.
5. **ПКМ** — удалить последнюю вершину.
6. **Escape** — отменить всю линию.

Минимум 2 вершины. Snap-to-first (замыкание) отсутствует намеренно — полилиния всегда остаётся открытой.

### Хранение и экспорт

Хранится как список `[[x, y], ...]` в нормализованных координатах.

| Формат | Результат |
|--------|-----------|
| **YOLO Segment** | Вершины полилинии как незамкнутый контур |
| **COCO JSON** | `"segmentation"` с вершинами |

## Аннотация типа Keypoints / Pose (ключевые точки)

Pose — набор именованных ключевых точек (keypoints) на объекте, соединённых рёбрами скелета. Используется для оценки позы и разметки структурных элементов.

### Для каких задач применяется

Оценка позы человека (суставы тела), разметка конструктивных элементов (крепежи, узлы), анализ движения животных, задачи «где что находится» внутри объекта.

### Настройка скелета

Перед разметкой нужно задать скелет класса в **Schema → Edit Class Schema → вкладка Skeleton**:

- Добавить именованные точки (название отображается в превью при разметке).
- Задать рёбра (edges) между точками — они рисуются линиями при отображении.

Если скелет не задан — инструмент работает в свободном режиме: любое число точек, Enter для фиксации.

### Рабочий процесс

1. Выбрать класс типа **keypoints**.
2. Активировать инструмент **Pose** в тулбаре.
3. **ЛКМ** — разместить следующую ключевую точку. В превью отображается название точки и счётчик `(N / M)`.
4. **ПКМ** — отменить последнюю точку.
5. Фиксация:
   - Если скелет задан — **автоматически** после размещения всех N точек.
   - Иначе — **Enter** или **двойной клик**.
6. **Escape** — отменить всю аннотацию.

### Хранение и экспорт

Каждая точка хранится как `[x, y, v]` в нормализованных координатах, где `v` — видимость: `2` = видима, `0` = невидима (заглушка).

| Формат | Результат |
|--------|-----------|
| **YOLO Pose** | `class cx cy w h kp1x kp1y kp1v ...` |
| **COCO JSON** | `"keypoints": [x,y,v,...]`, `"num_keypoints"` |

## Аннотация типа Classification (метка изображения)

Classification — метка на уровне всего изображения без какой-либо геометрии. Отвечает на вопрос «что изображено на этом кадре», а не «где именно».

### Для каких задач применяется

Классификация сцен (день/ночь, помещение/улица), контроль качества (брак/норма), фильтрация датасета по содержимому кадра, мульти-лейбл разметка (изображение может получить несколько меток одновременно).

### Рабочий процесс

У класса типа `classification` нет инструмента рисования — кнопка появляется прямо в панели аннотаций:

1. Выбрать класс типа **classification** в панели классов.
2. В панели **Annotations** появляется кнопка **`+ Classify as "<имя>"`**.
3. Нажать кнопку — изображение получает метку этого класса.
4. Повторное нажатие той же кнопки заменяет существующую метку (дубликатов не создаётся).
5. Несколько классов типа `classification` — несколько независимых меток на одном изображении.

### Хранение и экспорт

Аннотация хранится без геометрии (`data = {}`), только `class_id`.

| Формат | Результат |
|--------|-----------|
| **YOLO Classify** | Структура папок: `classify/train/<classname>/image.jpg` |
| **COCO JSON** | Категория уровня изображения |
| **YOLO Detect/Seg** | Не применимо — нет геометрии |

## Аннотация типа Point (одиночная точка)

Point — простейший тип геометрии: одна точка, заданная нормализованными координатами `(x, y)` в диапазоне `[0, 1]`.

### Для каких задач применяется

| Задача | Пример |
|--------|--------|
| **Подсчёт объектов** | Люди на площади, автомобили на парковке, деревья с дрона — каждый объект маркируется точкой |
| **Разметка центроидов** | Центр дефекта, центр клетки под микроскопом — когда граница объекта не важна, важно лишь его местоположение |
| **Ориентиры / landmarks** | Разметка опор, столбов, люков, отдельных конструктивных элементов |
| **Мелкие объекты** | Когда объект занимает несколько пикселей и bbox/полигон избыточен |
| **Seed-точки для ML** | Начальные подсказки для моделей типа SAM или counting-сетей |

### Рабочий процесс

1. Выбрать класс типа **point** в панели классов.
2. Активировать инструмент **Point** в тулбаре (горячая клавиша `•`).
3. **ЛКМ** — точка фиксируется мгновенно, без Enter.
4. **Escape** — скрыть превью (отменяет незафиксированную точку).

Превью (полупрозрачный кружок) появляется при движении мыши и показывает, куда будет поставлена точка.

### Отображение на холсте

- Закрашенный кружок цветом класса (радиус **6 px** в экранных пикселях — не зависит от зума).
- Белая обводка для контрастности на любом фоне.
- При выделении — дополнительное кольцо вокруг точки.
- Подпись класса справа от точки.

### Экспорт

| Формат | Результат |
|--------|-----------|
| **YOLO Point** | 1-keypoint pose: `class cx cy 1.0 nx ny vis` |
| **COCO JSON** | Как keypoint-аннотация с одной точкой |
| **YOLO Detect/Seg** | Не применимо — используйте bbox/polygon для этих форматов |

## Инструмент Brush (рисование масок)

Brush Tool позволяет рисовать бинарную маску объекта кистью произвольного размера. Результат сохраняется как аннотация типа `MASK` — PNG-битмап плюс полигонный контур для отображения и экспорта.

### Рабочий процесс

1. Выбрать класс типа **mask** в панели классов.
2. Активировать инструмент **Brush** в тулбаре. Под курсором — пунктирный круг размером с кисть (масштабируется вместе с зумом).
3. **Зажать ЛКМ и вести** — рисовать кистью (или стирать в режиме Erase).
4. **Enter** или **двойной клик** — зафиксировать маску как новую аннотацию.
5. **Escape** — отменить все текущие мазки и начать заново.

### Параметры (Tool Props)

| Параметр | Описание | Дефолт |
|----------|----------|--------|
| **Brush size** | Радиус кисти в пикселях изображения | 20 |
| **Mode** | `draw` — рисовать, `erase` — стирать | draw |

### Редактирование существующей маски

- **Выделить** аннотацию MASK на холсте или в панели Annotations → активировать Brush Tool → маска автоматически загрузится в холст для дорисовки.
- Первый мазок в режиме **Erase** на пустом холсте автоматически загружает последнюю зафиксированную маску текущего класса.

### Хранение

Маска хранится в двух форматах одновременно:
- **PNG-битмап** (`.annproj/masks/<image_stem>_<ann_id>.png`) — исходный пиксельный массив (белый = объект, чёрный = фон). Экспорты Semantic Masks, COCO Instances и COCO Panoptic берут маску прямо из PNG, поэтому несвязные части маски не теряются.
- **Полигонный контур** (самая большая область) — извлекается из битмапа при коммите и используется для отображения на холсте и экспорта в YOLO Seg / LabelMe.

> Маска кисти — это **инстанс** (thing): каждая зафиксированная маска — отдельный объект. Чтобы размечать фон и области по классам, используйте семантическую кисть (раздел ниже).

## Семантический режим — инструмент Semantic brush (`S`)

В обычной кисти (`M`) каждая зафиксированная маска — отдельный объект. В семантическом режиме **кисть — это класс**: всё, что нарисовано классом `road`, становится одной областью «дорога» на изображении, сколько бы мазков ни было и сколько бы отдельных кусков ни получилось. Это классическая семантическая сегментация: каждый пиксель принадлежит не более чем одному классу.

### Для каких задач применяется

- Семантическая сегментация: дорога / тротуар / небо / растительность, типы поверхностей, землепользование на аэроснимках, ткани на медицинских снимках.
- Фон («stuff») для panoptic-сегментации — вместе с объектами, размеченными инстансными инструментами.
- Любая задача, где важна площадь области, а не число объектов.

### Настройка класса

1. **Schema → Edit Class Schema → `+ Add`**.
2. Тип аннотации — **`semantic`** (после создания класса тип не меняется).
3. Цвет класса — это цвет заливки области на холсте и в экспорте Semantic Masks (режим Color).

При выборе класса типа `semantic` на тулбаре автоматически активируется **▦ Semantic**, остальные инструменты рисования блокируются.

### Рабочий процесс

1. Выбрать класс типа **semantic** в панели классов (или цифрой на клавиатуре).
2. Инструмент **▦ Semantic** / клавиша **`S`** (переназначается в Project Settings → Hotkeys).
3. Под курсором — пунктирный круг размером с кисть.
4. **Зажать ЛКМ и вести** — рисуется полупрозрачный след мазка.
5. **Отпустить ЛКМ** — мазок сразу сохраняется в слой класса. Enter нажимать не нужно.
6. **Esc во время рисования** — мазок отменяется, ничего не сохраняется.
7. **Ctrl+Z** — отменяет весь последний мазок одним шагом, даже если он изменил несколько классов (например, отобрал пиксели у соседнего класса).
8. Сменить класс и продолжить — у каждого класса свой слой.

### Параметры (Tool Props)

| Параметр | Значения | Описание | Дефолт |
|----------|----------|----------|--------|
| **Brush size** | 1–500 | Радиус кисти в пикселях изображения | 20 |
| **Mode** | `draw` / `erase` | `draw` — закрашивать текущим классом; `erase` — снять разметку со всех семантических классов под кистью (пиксели становятся «неразмеченными») | draw |
| **Other classes** | `overwrite` / `keep` | Что делать, если мазок заходит на область другого семантического класса (см. ниже) | overwrite |

### Правила перекрытия классов

Семантические слои одного изображения **никогда не перекрываются** — пиксель принадлежит максимум одному классу.

| Режим | Поведение | Когда удобно |
|-------|-----------|--------------|
| **overwrite** | Мазок забирает пиксели у других классов: закрасили кусок «дороги» классом «тротуар» — он ушёл из дороги в тротуар | Исправление границ, перекраска |
| **keep** | Мазок рисует только в неразмеченные пиксели; чужие области не трогаются | Заливка фона вокруг уже размеченного: можно смело водить широкой кистью по краю |
| **erase** | Снимает разметку со всех семантических классов под кистью | Удаление лишнего, «void»-зоны |

> **Инстансные аннотации (MASK, полигоны, bbox и т.д.) семантическая кисть не трогает никогда** — это отдельный слой «объектов» поверх семантического «фона».

### Отображение и выбор

- Слой рисуется прямо из PNG — точно по пикселям, включая дырки и отдельные куски.
- Семантические слои лежат **под** инстансными аннотациями: клик по машине выделяет машину, клик по небу — слой «sky», клик по неразмеченному месту — ничего.
- В панели Annotations слой отображается как `road  [semantic]  (3 reg · 41.5%)` — число связных областей и доля площади изображения.
- Выделенный слой обводится контурами; **Delete** удаляет весь слой класса на этом изображении.
- Атрибуты и подклассы для слоя задаются как для обычной аннотации; при дорисовке они сохраняются.

### Хранение

- Одна аннотация `SEMANTIC` на пару «изображение + класс».
- Пиксели — PNG `.annproj/masks/<image_stem>_sem<class_id>_<rev>.png` (255 = класс, 0 = нет). **При каждой правке пишется новый файл** (`<rev>` меняется), а старый остаётся на диске — именно так работает Undo. Лишние файлы потом убирает очистка масок (см. раздел «Очистка неиспользуемых масок»).
- В JSON аннотации дополнительно хранятся: `polygons` — внешние контуры всех областей (для полигонных форматов), `bbox`, `area` (доля площади).

### Экспорт семантических слоёв

| Формат | Что получается |
|--------|----------------|
| **Semantic Masks** | Точная попиксельная маска из PNG. Семантические слои рисуются первыми, инстансы — поверх. Режимы binary / index / color как раньше |
| **YOLO Segment** | Одна строка-полигон на каждую связную область слоя (дырки теряются) |
| **COCO Instances** | Одна аннотация на слой; `segmentation` — полигоны всех областей **или** RLE (опция «Masks as») |
| **COCO Panoptic** | Слой класса-stuff → один сегмент; см. раздел Panoptic |
| **LabelMe** | Один `polygon` на каждую область |
| **YOLO Detect / OBB / Pose, Pascal VOC** | Пропускаются — у «фона» нет осмысленного bbox |

**Какой формат выбрать:**
- Обучаете YOLO-seg — **YOLO Segment** (фон станет набором полигонов-«объектов»).
- Обучаете классическую семантическую сеть (U-Net, DeepLab, SegFormer) — **Semantic Masks**, режим **Index**.

> **Index-маска в просмотрщике выглядит чёрной — это нормально.** Значение пикселя — номер класса из `classes.txt` (0 = фон, 1, 2, 3…), а не яркость, поэтому глазом их не отличить от чёрного. Именно такой формат ждут сети семантической сегментации. Чтобы проверить разметку глазами, сделайте тот же экспорт в режиме **Color** — каждый класс будет своим цветом.
- Обучаете Detectron2 / MMDetection / Mask2Former — **COCO Instances + RLE** или **COCO Panoptic**.

## Panoptic-сегментация (things + stuff)

Panoptic-сегментация объединяет два вида разметки на одном изображении:
- **things** — счётные объекты, каждый экземпляр отдельно: машины, люди, дефекты;
- **stuff** — аморфные области без экземпляров: дорога, небо, трава, вода.

Каждый пиксель изображения принадлежит **одному** сегменту: либо конкретному объекту, либо области класса-фона, либо «void» (не размечен).

### Роль класса (Panoptic role)

В **Schema → Edit Class Schema** у каждого класса есть поле **Panoptic role**:

| Роль | Смысл |
|------|-------|
| **auto** (по умолчанию) | Класс `semantic` → stuff; все остальные типы → thing |
| **thing** | Каждая аннотация класса — отдельный сегмент-экземпляр |
| **stuff** | Все аннотации класса на изображении сливаются в один сегмент |

Роль можно менять в любой момент (в отличие от типа аннотации) — она влияет только на экспорт. Пример: класс `vegetation` типа `polygon` с ролью **stuff** — можно обводить кусты полигонами, а в panoptic они станут одной областью «растительность».

### Как размечать panoptic-сцену (пример: улица)

1. Классы-фон: `road`, `sidewalk`, `sky`, `building` — тип **semantic** (роль auto = stuff).
2. Классы-объекты: `car`, `person` — тип **mask**, **polygon** или **bbox** (роль auto = thing).
3. Сначала закрасить фон семантической кистью `S` — удобно широкой кистью в режиме `keep`.
4. Затем разметить объекты инстансными инструментами (`M`, `P`, `B`) поверх фона. Фон под объектами дорисовывать не обязательно — в экспорте объект всё равно перекроет фон.
5. Проверить: клик по объекту выделяет объект, клик по фону — слой класса.

### Экспорт COCO Panoptic

**File → Export Dataset → Single format → COCO Panoptic**

```
output/
  annotations/
    panoptic_train.json
    panoptic_train/
      img001.png        ← RGB, id сегмента = R + 256·G + 256²·B; 0 (чёрный) = void
  images/train/         ← копии изображений (если включено)
```

Пример `panoptic_train.json`:
```json
{
  "categories": [
    {"id": 0, "name": "road", "isthing": 0, "color": [128, 64, 128], "supercategory": ""},
    {"id": 2, "name": "car",  "isthing": 1, "color": [0, 0, 142],   "supercategory": ""}
  ],
  "images": [{"id": 0, "file_name": "img001.jpg", "width": 1920, "height": 1080}],
  "annotations": [{
    "image_id": 0,
    "file_name": "img001.png",
    "segments_info": [
      {"id": 8405120, "category_id": 0, "area": 812345, "bbox": [0, 540, 1920, 540], "iscrowd": 0},
      {"id": 9831692, "category_id": 2, "area": 20411,  "bbox": [210, 600, 180, 95], "iscrowd": 0}
    ]
  }]
}
```

**Правила построения:**
- Сначала рисуются все stuff-классы (каждый — один сегмент), затем things поверх них; среди things более поздняя аннотация перекрывает более раннюю.
- `area` и `bbox` считаются по **видимой** части сегмента; объект, полностью закрытый другими, в `segments_info` не попадает.
- Растеризуются типы MASK, SEMANTIC (точно из PNG), POLYGON, POLYLINE (толстая линия), BBOX, OBB. Классы типов keypoints / point / classification в категории не попадают.
- id сегментов выбираются рядом с цветом класса (stuff — точно цвет класса, things — оттенки), поэтому PNG можно открыть и визуально проверить.

### COCO Instances: «Masks as» — полигоны или RLE

При выборе формата **COCO Instances** в диалоге появляется опция **Masks as** — она влияет только на маски кисти (MASK) и семантические слои (SEMANTIC); bbox / полигоны / OBB всегда экспортируются полигонами.

| Вариант | Что пишется в `segmentation` | Плюсы | Минусы |
|---------|------------------------------|-------|--------|
| **Polygons** (по умолчанию) | Список полигонов — по одному на каждую связную область | Читается глазами и любыми инструментами, редактируется | Дырки теряются; контур слегка упрощается |
| **RLE** | `{"size": [H, W], "counts": "…"}` — сжатая попиксельная маска | Точно по пикселям, дырки сохраняются | Не читается глазами; некоторые инструменты RLE не понимают |

**RLE (Run-Length Encoding)** — маска записывается как длины чередующихся серий «фон / объект», по столбцам. Формат совместим с pycocotools, Detectron2, MMDetection, Mask2Former (проверено побайтовым сравнением с pycocotools); сам pycocotools для экспорта не нужен.

`area` для масок — точное число пикселей, `bbox` — по пикселям маски.

### Какой экспорт для какой модели

| Модель / фреймворк | Экспорт |
|--------------------|---------|
| Ultralytics YOLO (seg) | YOLO Segment — полигоны |
| U-Net / DeepLab / SegFormer (семантика) | Semantic Masks, режим Index |
| Detectron2 / MMDetection (инстансы) | COCO Instances + RLE |
| Mask2Former / OneFormer / Panoptic-DeepLab | COCO Panoptic |

## Очистка неиспользуемых масок

Маски кисти и семантические слои хранятся как PNG в `.annproj/masks/`. Каждая правка пишет новый файл (чтобы работал Undo), поэтому со временем копятся файлы, на которые уже никто не ссылается. Они убираются автоматически **при открытии проекта**, в два этапа:

1. Файл, на который не ссылается ни одна аннотация **и** которому больше **24 часов**, переносится в `masks/_orphaned/`.
2. При **следующем** открытии проекта содержимое `_orphaned/` удаляется. Если на файл снова появилась ссылка — он возвращается в `masks/`.

Защиты:
- 24-часовая отсрочка — чтобы не задеть свежие мазки другого разметчика в многопользовательском режиме, чей JSON ещё не автосохранился.
- Если хотя бы один файл аннотаций не читается (повреждён) — очистка полностью отменяется.
- До следующего открытия проекта файлы в `masks/_orphaned/` можно вручную просмотреть или вернуть.

## Риски и ограничения (семантический режим и panoptic)

| Ограничение | Последствие / что делать |
|-------------|--------------------------|
| **Полигонные форматы не хранят дырки** | YOLO Segment, COCO (Polygons), LabelMe получают только внешние контуры: «дорога вокруг люка» станет сплошной. Точная форма — в PNG, Semantic Masks, COCO RLE, COCO Panoptic |
| **Мелкие области < 4 px** | Отбрасываются из `polygons` (в PNG остаются) |
| **Масочные файлы копятся** | Каждый мазок пишет новый PNG; удаляются не раньше чем через 24 ч и одно повторное открытие проекта |
| **Большие изображения** | После каждого мазка сцена перестраивается; неизменённые слои берутся из кэша, но на снимках ~20 Мп возможна небольшая задержка после отпускания кнопки |
| **Скорость COCO Panoptic** | Каждый сегмент обрабатывается отдельным проходом; при сотнях объектов на снимке 12 Мп — порядка секунды на изображение |
| **Erase снимает все классы** | Стирание семантической кистью очищает пиксели любого семантического класса, а не только текущего. Чтобы убрать только свой класс — закрасьте область нужным классом в режиме `overwrite` |
| **Семантическая кисть — только для классов `semantic`** | На классе другого типа инструмент ничего не делает и пишет подсказку в статусной строке |
| **PanopticFPN (Detectron2)** | Кроме panoptic-PNG ему нужна отдельная семантическая карта stuff-классов — пока не экспортируется (Mask2Former / OneFormer достаточно COCO Panoptic) |
| **Роль stuff у инстансных классов** | Если назначить `stuff` классу `mask`/`polygon`, все его объекты на изображении сольются в один сегмент — это ожидаемо, но легко забыть |
| **YOLO не знает про stuff** | В YOLO Segment семантический слой превращается в набор отдельных полигонов-«объектов» по числу областей |

## Инструмент Crack Tool

> **Встроенный инструмент** — входит в состав приложения, не требует плагина. Для добавления собственных инструментов используйте систему плагинов (см. раздел ниже).

Crack Tool рисует полилинию (набор точек), которая автоматически превращается в расширенный (буферизованный) полигон — класс `SEGMENT`. Предназначен для разметки трещин, дорог, кабелей и любых протяжённых объектов с нужной шириной.

### Создание разметки

1. Выбрать инструмент **Crack** в тулбаре (горячая клавиша `C`).
2. **ЛКМ** — добавить точку полилинии. Каждый клик добавляет вершину в конец линии.
3. **ПКМ** — удалить **последнюю** добавленную точку.
4. Нажать **Enter** или **двойной клик** — зафиксировать разметку.
5. **Escape** — отменить и начать заново.

> Буферизованный полигон отображается **live** во время рисования — видно, как будет выглядеть результат.

### Перемещение вершин во время рисования

Нажать и удерживать ЛКМ **на существующей точке** → перетащить в новое место. Превью обновляется live. ПКМ во время перетаскивания — отменить перетаскивание.

### Параметры буфера (Tool Props)

Панель **Tool Props** появляется под тулбаром, когда активен Crack Tool:

| Параметр | Описание | Дефолт |
|----------|----------|--------|
| **Buffer width** | Полуширина разметки (0–1, нормализована к min-стороне изображения) | 0.008 |
| **Cap style** | Форма торцов линии: `round`, `flat`, `square` | round |
| **Join style** | Форма углов: `round`, `mitre`, `bevel` | round |
| **Simplify** | Упрощение результирующего полигона | 0.001 |

Изменения параметров обновляют превью **немедленно** — до фиксации.

### Редактирование уже созданной разметки

Каждая crack-разметка хранит **исходную полилинию** внутри файла аннотаций (`source_geometry`). Именно её можно редактировать после создания.

**Кнопка "Edit source"** (внизу панели Annotations):

1. Выделить crack-разметку (клик на канвасе или в списке Annotations).
2. Нажать кнопку **Edit source** — активна только для crack-аннотаций.
3. CrackTool активируется, исходная полилиния загружается на канвас (узлы видны, резиновой нити нет).
4. **Параметры буфера** в Tool Props автоматически выставляются в те значения, с которыми создавалась эта разметка.
5. Отредактировать полилинию:
   - **Перетащить** существующую вершину — зажать ЛКМ на узле и тянуть. Буферный полигон обновляется live.
   - **Добавить точку** в конец — кликнуть ЛКМ в пустом месте (не на существующем узле).
   - **Удалить последнюю точку** — ПКМ (если не идёт перетаскивание).
   - **Изменить параметры буфера** — поменять значения в Tool Props, превью пересчитывается немедленно.
6. **Enter** или **двойной клик** — подтвердить изменения. Полигон пересчитывается заново. Операция отменяема (Ctrl+Z).
7. После подтверждения инструмент автоматически переключается на **Select**, аннотация остаётся выделенной — кнопка Edit source снова активна для повторного редактирования.

> **Что такое "Edit source"**: crack-разметка на канвасе — это буферизованный **полигон**. Его нельзя редактировать как обычный полигон (вершины полигона — это результат буферизации, не исходные точки). "Edit source" даёт доступ к исходной **полилинии**, из которой полигон был вычислен.

## QC — контроль качества датасета

**QC (Quality Control)** — это встроенный слой проверки, который анализирует весь датасет и выявляет типичные проблемы, ведущие к ухудшению качества обучения модели.

### Зачем нужен QC?

Ошибки в разметке напрямую влияют на качество обученной модели: пропущенные объекты снижают recall, дублирующиеся аннотации вводят шум в функцию потерь, слишком маленькие полигоны деградируют в артефакты. QC позволяет обнаружить эти проблемы до экспорта датасета.

### Как запустить

- Меню **QC → Validate Project** (горячая клавиша `Ctrl+Shift+V`)
- Кнопка **▶ Validate** на вкладке **QC** в правой панели

### Правила валидации

#### 1. Empty Image (Пустое изображение)

**Что проверяет:** изображения, у которых нет ни одной аннотации.

**Почему важно:** если изображение добавлено в проект, но не размечено, модель при обучении получает неоднозначный сигнал. В большинстве форматов экспорта пустой файл меток означает «объектов нет», что может быть как правдой, так и ошибкой разметчика.

**Severity:** `warning` (предупреждение).

**Действие:** проверьте каждое помеченное изображение — либо добавьте аннотации, либо явно исключите изображение из датасета, если оно действительно «негативное» (без объектов).

---

#### 2. Small Polygon (Слишком маленький полигон)

**Что проверяет:** полигоны типа `SEGMENT`, площадь которых в нормализованных координатах меньше порогового значения (по умолчанию `0.001`, то есть 0.1% площади изображения).

**Как вычисляется площадь:** по формуле Гаусса (shoelace) для нормализованных координат вершин полигона:

```
S = 0.5 × |Σ (xᵢ·yᵢ₊₁ − xᵢ₊₁·yᵢ)|
```

**Почему важно:** очень маленькие полигоны, как правило, являются артефактами случайного клика или «мусорными» аннотациями. При обучении они создают нестабильный градиент из-за крайне малой площади маски. Такие объекты обычно неразличимы на уровне признаков модели.

**Severity:** `warning`.

**Действие:** удалите случайный полигон или исправьте вершины. Если объект действительно маленький, рассмотрите использование bbox вместо полигона.

---

#### 3. Duplicate Annotation (Дублирующаяся аннотация)

**Что проверяет:** пары аннотаций одного класса на одном изображении, у которых IoU (Intersection over Union) ≥ порогового значения (по умолчанию `0.85`).

**Как вычисляется IoU:** для bbox-аннотаций — через пересечение прямоугольников. Для полигонов и полилиний — через их описывающие прямоугольники (bbox-аппроксимация).

```
IoU = Площадь пересечения / Площадь объединения
```

**Почему важно:** дублирующиеся аннотации — частая ошибка при разметке, когда объект обведён дважды. Это удваивает «вес» объекта в функции потерь и ухудшает метрики mAP при оценке.

**Severity:** `warning`.

**Действие:** на вкладке QC дважды кликните на проблему — программа перейдёт к нужному изображению и выделит аннотацию. Удалите лишний дубликат.

---

### Статистика датасета

Помимо правил, QC отображает общую статистику:

| Метрика | Описание |
|---------|----------|
| **Coverage** | Доля размеченных изображений (labeled / total × 100%) |
| **Total annotations** | Общее количество аннотаций в датасете |

### Экспорт отчёта

- **QC → Export Report (CSV)** — табличный формат для Excel/Google Sheets: колонки `severity`, `rule`, `image`, `ann_id`, `message`

## Параметры визуального отображения

### Отображение готовых аннотаций (canvas items)

Настраиваются **per-class** через Schema Editor → Display style. Дефолты и константы:

| Параметр | Файл | Константа / поле |
|----------|------|-----------------|
| Размер хэндла выделения (экр.пикс.) | `ui/canvas/items/polygon_item.py`, `bbox_item.py`, `obb_item.py`, `pose_item.py` | `HANDLE_SCREEN_R = 5.0` |
| Зона клика на хэндл (scene units) | те же файлы | `HANDLE_HIT = 9.0` |
| Отступ хэндла поворота OBB | `ui/canvas/items/obb_item.py` | `ROTATION_OFFSET = 22.0` |
| Толщина линии (дефолт, экр.пикс.) | `ui/canvas/items/base_item.py` | `self.line_width = 2.0` |
| Заливка (дефолт) | `ui/canvas/items/base_item.py` | `self.fill_opacity = 0.3` |

Все контуры аннотаций используют **cosmetic pens** (`QPen.setCosmetic(True)`) — толщина задаётся в экранных пикселях и не зависит от разрешения изображения или уровня зума. Это обеспечивает одинаковый внешний вид на фотографиях любого разрешения.

Подписи классов отображаются шрифтом **12px bold** в экранных координатах (с тёмной тенью для читаемости) — также не зависят от разрешения изображения.

Значения `line_width` и `fill_opacity` переопределяются из `display_style` класса в `scene.py → _make_item()`.

### Превью при рисовании (tools)

Действуют **во время отрисовки** — до фиксации разметки. Не зависят от настроек класса.

| Параметр | Файл | Место |
|----------|------|-------|
| Превью bbox (цвет, alpha, толщина) | `tools/bbox_tool.py` | `QColor("#FFFF00")`, alpha 70, width 2.0px, cosmetic |
| Превью OBB (цвет, alpha, толщина) | `tools/obb_tool.py` | `QColor("#FFAA00")`, alpha 70, width 2.0px, cosmetic |
| Размер точки-узла (экр.пикс.) | `tools/polygon_tool.py`, `tools/crack_tool.py` | `dot_r = 5.0 / lod` в `_refresh_preview()` |
| Размер кольца замыкания полигона (экр.пикс.) | `tools/polygon_tool.py` | `snap_r = 11.0 / lod` в `_refresh_preview()` |
| Зона замыкания контура (экр.пикс.) | `tools/polygon_tool.py` | `CLOSE_THRESHOLD_SCREEN = 15` |
| Заливка превью CrackTool (alpha 0–255) | `tools/crack_tool.py` | `QColor(255, 170, 0, 90)` в `_refresh_preview()` |
| Базовые хелперы масштабирования | `tools/base.py` | `_view_lod()`, `_cosmetic_pen()` |

Все размеры превью — в **экранных пикселях**, автоматически пересчитываются в координаты сцены через `_view_lod()` — поэтому выглядят одинаково при любом зуме и разрешении изображения.

## Система плагинов (пользовательские инструменты)

Annotator поддерживает расширение через плагины — `.py`-файлы с пользовательскими инструментами, которые обнаруживаются автоматически при запуске приложения.

### Как добавить плагин

1. Создать `.py`-файл в папке `new_annotator/plugins/`.
2. Определить класс, наследующий `BaseTool` из `annotator.tools.base`.
3. Реализовать обязательные методы и свойство `name`.
4. Запустить приложение — инструмент появится в тулбаре автоматически.

Файлы с именем, начинающимся на `_`, загрузчиком пропускаются. Ошибка в одном плагине не влияет на остальные и не мешает запуску приложения.

### Шаблон

В папке `new_annotator/plugins/` уже есть готовый шаблон `example_tool.py`:

```python
from annotator.tools.base import BaseTool

class MyCustomTool(BaseTool):

    @property
    def name(self) -> str:
        return "my_tool"          # уникальный ключ инструмента

    def activate(self, scene, controller=None):
        self._scene = scene
        self._ctrl = controller

    def deactivate(self):
        self._scene = None

    def on_press(self, pos, modifiers, button):
        pass   # создать аннотацию в точке pos

    def on_move(self, pos, modifiers):
        pass   # обновить превью

    def on_release(self, pos, modifiers, button):
        pass   # зафиксировать результат
```

### Доступные методы BaseTool

| Метод | Когда вызывается |
|-------|-----------------|
| `activate(scene, controller)` | При активации инструмента |
| `deactivate()` | При переключении на другой инструмент |
| `on_press(pos, modifiers, button)` | Нажатие кнопки мыши |
| `on_move(pos, modifiers)` | Движение мыши |
| `on_release(pos, modifiers, button)` | Отпускание кнопки мыши |
| `on_double_click(pos, modifiers, button)` | Двойной клик |
| `on_key_press(key, modifiers)` | Нажатие клавиши |
| `set_class(class_id)` | Смена активного класса |

Координаты `pos` передаются в пикселях сцены (= пикселях изображения). Для создания аннотаций используется `controller.add_annotation(ann)`.

## Структура хранилища проекта

```
MyProject.annproj/
├── project.json          — мета-данные проекта и настройки (leader_machine)
├── images.json           — список изображений (path, width, height, split)
├── class_schema.json     — схема классов (id, name, color, annotation_type, ...)
├── assignments.json      — назначения изображений разметчикам (многопользоват.)
├── annotations/
│   ├── image001.json     — аннотации для каждого изображения
│   ├── image002.json
│   └── ...
└── masks/
    ├── image001_<ann_id>.png         — маска кисти (MASK)
    ├── image001_sem<cls>_<rev>.png   — семантический слой (SEMANTIC), новый <rev> на каждую правку
    └── _orphaned/                    — неиспользуемые маски, ждут удаления
```

`images.json` хранит реальные размеры каждого изображения (`width`, `height` в пикселях), которые считываются при добавлении файлов в проект.

## Версии внутреннего формата

| Версия | Изменение |
|--------|-----------|
| `FORMAT_VERSION=1` | Базовая структура: project.json, images.json, annotations/ |
| `FORMAT_VERSION=2` | YOLO auto-export при flush, autosave таймер |
| `FORMAT_VERSION=3` | Схема классов вынесена в отдельный `class_schema.json` |
| `SCHEMA_VERSION=1` | Расширенный LabelClass: annotation_type, allowed_tools, subclasses, attributes, display_style |
| v1.5 (без смены версий) | Тип аннотации `semantic`, поле класса `panoptic_role` (`auto` по умолчанию) — старые проекты открываются без миграции |
