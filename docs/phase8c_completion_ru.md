# Фаза 8-C — автотрекинг моделью: отчёт

## Итог

В окне **ML → Разметить датасет моделью…** в списке «Какие изображения» появились видео проекта (**🎞 Видео: имя (кадров: N)**). При выборе видео доступны галочка **«Отслеживать объекты (видео)»** и выбор трекера: ByteTrack или BoT-SORT. Модель проходит кадры по порядку, трекер связывает объекты между кадрами.

- **Каждый объект становится треком проекта со своим номером, каждая найденная рамка — ключевым кадром.** Рамки помечены 🤖 и не проверены, поэтому дальше идёт обычная приёмка: `U` / `Shift+R` / `R`.
- **Кадры, где модель объект пропустила, заполняются интерполяцией** (код треков из 8-B).
- **Рамки, которые трекер не подтвердил, не добавляются.** В итоге они посчитаны как «трекер не подтвердил».
- **Повторный прогон заменяет непроверенные ключевые кадры прошлого прогона и их интерполяцию.** Принятые (✓🤖) и ручные аннотации остаются. Режим «пропускать» при трекинге отключён: трекеру нужен каждый кадр.
- **Работает с моделями детекции, сегментации, OBB и поз.** Сочетается с «Контурами через SAM»: детектор + SAM дают треки полигонов или масок.
- **Итог прогона:** «Треки: новых — N, кадров заполнено интерполяцией — M».

Проверено на реальной модели (yolo11m, RTX 5060 Ti):
- **кадры шоссе:** номера держатся на одних машинах от кадра к кадру. При шаге 6 (5 кадров/с) быстрые машины теряются — отсюда подсказка импортировать для трекинга каждый 1–3-й кадр;
- **сквозной тест** (8 кадров «панорамы» по `bus.jpg`): 5 треков, автобус и двое людей с одними номерами на всех кадрах, 3,8 с вместе с запуском сервера.

## Как устроено

```
PrelabelDialog (видео + «Отслеживать») ─► PrelabelRunner(track=True)
   кадр за кадром ─► yolo.track (reset на первом кадре видео) ─► convert (meta.model_track)
   ─► номер трекера → новый номер трека проекта (keyframe, 🤖) ─► apply_annotation_changes
   в конце ─► plan_track для новых треков и треков заменённых кадров ─► sync_derived
```

- **Сервер — `yolo.track`.** Те же параметры, что у `yolo.predict`, плюс `reset` и `tracker`; в каждой рамке есть `track_id`. Трекинг идёт на **отдельном экземпляре модели**: Ultralytics навсегда цепляет трекер к модели, и он испортил бы обычный `yolo.predict`. Тест это проверяет.
- **Разбор результата** для `predict` и `track` вынесен в общую функцию `_result`.
- **`convert()`** кладёт номер трекера в `meta["model_track"]`; запуск переводит его в номер трека проекта и удаляет этот ключ.
- **Трекинг встроен в предразметку, а не сделан отдельным окном.** Модель, сопоставление классов, пороги, SAM, прогресс и «Стоп» общие.
- **`lap`** (нужен трекерам Ultralytics) добавлен в `requirements-ml.txt`. В уже существующем conda-окружении Ultralytics ставит его сам при первом трекинге (в `yolo_hard` он так и установился во время проверки).

## Риски и ограничения

- Для трекинга нужны плотные кадры: каждый 1–3-й. На редких кадрах быстрые объекты теряются.
- Повторный прогон рядом с принятым ключевым кадром старого трека создаёт новый трек на том же объекте. Лишний удаляется «Удалить активный трек…».
- Трекинг идёт подряд по кадрам одного видео. «Все изображения» трекинг не включает: нужно выбрать видео.
- SAM 2 для видео (распространение маски по кадрам) не сделан.
