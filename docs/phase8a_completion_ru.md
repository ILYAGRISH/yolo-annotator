# Фаза 8-A — приёмка предразметки: отчёт

## Итог

У аннотаций модели (🤖) появился статус **«проверено»**. Программа помнит, что уже просмотрено, показывает остальное и ведёт по нему.

- **Холст:** непроверенная аннотация модели — пунктир, заливка вдвое бледнее, 🤖 у подписи. Принятые и ручные — как обычно.
- **Панель «Аннотации»:** непроверенные — оранжевые «🤖 0.87», принятые — «✓🤖 0.87» (в подсказке — кто принял), в заголовке «🤖 не проверено: N».
- **Список изображений:** «🤖N» у изображений с непроверенным; в фильтре статуса — **🤖 Не проверено**.
- **Меню «Приёмка»:** `R` — принять выделенную (выделение переходит на следующую непроверенную; строка в панели не сбрасывается на первую при обновлении списка); `Shift+R` — принять всё на изображении и перейти к следующему изображению с 🤖; `U` — перейти, не принимая; «Вернуть выделенную в непроверенные». Клавиши настраиваются в Hotkeys проекта.
- **Правка = приёмка:** сдвиг, правка вершин или атрибутов аннотации модели помечает её проверенной в том же шаге отмены. «Правка», которая ничего не меняет, статус не трогает.
- **QC:** правило *Unreviewed* (`info`, одно на изображение, двойной клик — к первой непроверенной); в статистике строка **🤖 Review** — «принято / всего · не проверено: K (M img)».
- **Экспорт:** галочка **Skip unreviewed 🤖 annotations (K on M images)** — видна, только если есть непроверенное; по умолчанию выключена. Работает для одиночного формата и для multi-task.
- **ML:** повторная предразметка в режиме «заменять» и `Ctrl+L`, а также «Удалить разметку модели» трогают только **непроверенные** аннотации — принятые сохраняются, как ручные.

## Формат

Только `meta` аннотации, новых файлов нет:

```json
"meta": {"source": "model", "confidence": 0.87, "model": "best.pt",
         "reviewed": true, "reviewed_at": "2026-10-08T21:14:03", "reviewed_by": "Ilya"}
```

`reviewed_by` берётся из «Ваше имя…» (или из имени лидера / участника в многопользовательском режиме) и пишется, только если имя известно. Старые проекты открываются без изменений: их аннотации модели считаются непроверенными. Ручные и SAM-аннотации статуса не имеют.

## Как устроено

- `domain/review.py` — вся логика статуса: `is_model`, `is_unreviewed`, `reviewed_meta`, `drop_unreviewed` (для экспорта), `count_unreviewed_in_file`. Последняя — быстрый подсчёт по JSON: файлы без `"model"` не разбираются.
- Undo: новая команда `SetMetaCmd` (статус нескольких аннотаций за один шаг). `UpdateAnnotationCmd` умеет менять `meta` вместе с данными — так правка принимает аннотацию, а `Ctrl+Z` возвращает и геометрию, и пунктир.
- `ProjectController`: `set_reviewed(ids|None, reviewed)`, `unreviewed_counts()`, `reviewer` (функция, возвращающая имя), `reviewed_only` в `export_dataset` / `export_multitask` (сбор аннотаций вынесен в `_annotations_for_export`).
- Холст: у `BaseAnnotationItem` флаг `unreviewed` и свойство `outline_style`; все виды аннотаций рисуют им основной контур.

## Риски и ограничения

- Принять весь датасет одной командой нельзя — только по изображению (так задумано).
- Автоэкспорт YOLO-меток в `labels/` рядом с изображениями пишет все аннотации; «только проверенные» — через «Экспорт датасета».
- Подсчёт 🤖 в списке изображений при открытии проекта читает JSON только тех изображений, где есть аннотации модели. На очень больших проектах с предразметкой открытие станет чуть дольше.
- `U` и `Shift+R` ходят только по изображениям, показанным в списке (с учётом фильтров и назначений в многопользовательском режиме).
