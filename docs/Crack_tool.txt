2. Crack Tool — обсуждение перед Phase 6
Из roadmap и §9 у нас уже есть спецификация. Вот открытые вопросы, которые нужно решить до реализации:

А. Как хранить исходную геометрию?

Crack Tool берёт полилинию от пользователя → применяет буфер → выдаёт полигон. Полигон нужно пересоздавать при изменении параметров (ширина буфера). Значит исходная линия должна где-то жить. Варианты:

annotation.data["source_polyline"] — хранить прямо в аннотации рядом с полигоном
Отдельная polyline-аннотация-невидимка, связанная с полигоном через source_id
Первый вариант проще, второй чище архитектурно но сложнее в UI.

Б. Как регистрируются плагинные инструменты?

Папка plugins/ — Python-файлы, загружаются при старте
Или встроенные кастомные инструменты (crack_tool просто часть кода, не плагин)
Crack Tool — это единственный пример из roadmap. Возможно, Phase 6 = "crack tool как встроенный инструмент" без полноценного plugin API. Plugin API с регистрацией через папку — это уже Phase 7+.
